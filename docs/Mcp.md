# 로컬 MCP 앱 제어

데스크톱 POSIX에서 공개 MCP의 소유자는 Society 데몬이며 식별자는
`com.iisacc.society`이다. GUI가 닫혀도 데몬과 저장소 도구는 유지된다.
서버는 로컬 `127.0.0.1`에 바인딩하며 등록 파일에 있는 사용자 전용 토큰으로
인증한다. `IILOCALLLM_DISABLE_APP_MCP=1`이면 공개 서버를 열지 않는다.

- 도구: `status`; 동작: 데몬 상태와 연결된 화면의 기존 탐색 상태
- 도구: `ui_status`; 동작: 연결된 화면의 현재 경로·섹션과 가용 상태
- 도구: `open_section(key)`, `navigate(path)`, `refresh`; 동작: 연결된 Society 화면의 탐색과 새로 고침
- 도구: `list_entries(path, offset, limit)`; 동작: 현재 폴더 또는 지정 폴더의 최대 200개 항목
- 도구: `file_job_submit`, `file_job_status`; 동작: 파일 작업 제출과 지속 작업 상태 조회
- 도구: `model_import_submit`; 동작: 로컬 safetensors를 데몬 모델 작업에 제출
- 도구: `semantic_read`, `semantic_relations`; 동작: 주소의 의미 정보와 관계 조회
- 도구: `semantic_set_metadata`, `semantic_set_relation`, `semantic_remove_relation`, `semantic_rebind`; 동작: 명시적 의미 정보·관계 변경
- 도구: `AskUserQuestion`; 동작: 연결된 화면에 사용자 질문 전달
- 도구: `iiLocalLLM.agent.permissions.get`; 동작: SDK 호스트 권한 정책 조회

목록에서 `path`를 명시하지 않으면 연결된 화면의 현재 폴더를 사용하고, 화면이 없으면
`Files`를 사용한다. `offset` 기본값은 0, `limit` 기본값은 100, 최대값은 200이다.
각 호출은 데몬의 비동기 목록 세션 하나를 사용하며 내부 메타데이터를
독립 항목으로 표시하지 않는다. 반환된 세대와 리비전은 그 페이지의 관측값이고
다른 호출의 스냅샷 고정을 뜻하지 않는다. 파일·모델 작업의 수락은 완료가 아니며
작업 ID로 결과를 확인한다. 응답을 받기 전 연결이 끊긴 제출은 자동 재전송하지 않는다.
명시적 상대 경로 목록은 상대 경로를 반환하고, 화면 기반 기존 호출은 절대 경로와
`kind`, `truncated`를 함께 반환한다. `status`는 데몬 상태를 우선 제공하며 연결된
화면이 빠르게 응답하면 기존 화면 상태도 포함한다. 원본 데몬 상태는 `backend`에
별도로 남으며 화면 미응답은 데몬 상태 조회를 막지 않는다. 화면이 연결된 경우
기존 `busy`는 화면 상태를 가리키므로 모델 작업 상태는 `backend.busy`로 확인한다.
`file_job_submit`의 `copy`는 `path`에 정규 절대 원본 경로, `argument`에 컨테이너
상대 대상 폴더를 받는다. 원본을 유지하고 내부 메타데이터와 미리보기는 컨테이너의
객체 복사 규칙에 따라 처리한다.

화면 제어와 질문의 공개 도구는 데몬에 있고, 실제 화면 조작과 입력 수신은 GUI의
비공개 임시 연결에 위임한다. 화면이 없거나 연결이 끊기면 해당 요청에 사용 불가를
반환한다. 저장소 도구는 화면의 수명과 독립적이다. 데몬이 종료될 때 공개 서버를
백엔드 스레드보다 먼저 닫아 진행 중인 요청을 정리한다.

GUI와 데몬은 로컬 소켓 상대의 사용자와 운영체제가 제공한 프로세스 ID를 확인하고,
상대 실행 파일이 같은 앱 번들의 Society 또는 SocietyDaemon과 일치할 때만 화면
연결을 등록한다. GUI는 이 소켓 연결의 클라이언트이며 별도 MCP 서버를 열지 않는다.
데몬 자신만 화면 요청을 제출할 수 있고, GUI 연결에서 돌아온 응답만 결과로 받는다.
요청자가 연결을 끊거나 취소하면 화면 요청도 취소한다. 공개 MCP 등록 파일은 같은 사용자에게 읽힐 수
있으며 별도의 코드 서명 검증을 뜻하지 않는다.

로컬 등록 경로는 `IILOCALLLM_APP_ENDPOINTS` 또는 사용자 데이터의
`iisacc/AgentEndpoints`이다. 현재 사용자 소유의 0700 폴더와 0600 파일을 사용한다.
토큰을 로그나 모델 프롬프트에 넣지 않는다. 모바일과 Windows에는 공개 리스너를
추가하지 않는다.

## 로컬 질문 화면

`AskUserQuestion`의 공개 입력에는 답변과 주석을 주입할 수 없다. 데몬은 요청의
유효성을 확인한 뒤 연결된 화면의 QuestionInbox로 전달한다. 화면에서 확인한 답변만
원래 요청에 반영한다. 도구 대기 중 다른 호출은 계속 처리하며 요청 취소·화면 종료는
대기와 내부 요청을 해제한다. 화면 연결은 질문 대기와 화면 동작을 별도의 제한된
작업 풀에서 처리한다. 기존 질문 화면은 아직 QML·LVRS이며 LVUI로의 시각
이관은 별도 작업이다.

`Society.DaemonMcp`, `Society.LocalBackendPeerIdentity`, `Society.UiBridge`는
창 없는 호출, 프로세스 식별, 등록 거절, 연결 해제, 질문 위조 거절과 취소를 격리된
로컬 환경에서 검사한다. `Society.Mcp`는 GUI를 포함하는 별도 통합 검사이다. 이
검사와 설치된 앱 또는 실제 운영체제 화면 검증은 구분한다.

## 과거 검증 기록

2026-09-15 최종 SDK 조합으로 macOS 전체 CTest 21/21(272.48초)을 통과했다. 새 패키지의 서명과 번들 내부 의존성을 검사한 뒤, Qwen3 8B가 만든 질문에 에이전트가 네이티브 앱 화면으로 입력한 임의 코드를 모델이 2턴·98토큰으로 정확히 반환했다. 코드는 최초 모델 입력에 없으며 도구 선택과 응답 형식은 검증 호스트가 제한했다. 첫 모델 실행은 화면 입력 전에 서버의 60초 기한으로 실패했으며 재검사는 통과했다. 서비스 등록 명령의 최초 30초 시간 초과는 등록 상태를 조회하고 재등록하여 enabled로 복구했다. 일반 iOS Release도 iPad 설치 영수증과 실행 프로세스를 확인했다. 교차 저장소 증거는 `SDK/iiLocalLLM/build/question-ui-apps/`의 최종 검사·패키지·UI·iPad 보고서에 보존한다.

## 2026-09-24 SDK 재설치 기준

당시 빌드는 iiLocalLLM 0.52 계열 설치본을 사용했다. 당시 MCP 통합 테스트는
설치본과 실제 제품 프로세스를 연결하여 도구 호출, 인증, 경로 제한과
호스트의 rules 기반 기본 권한 모드를 검증했다. 위의 2026-09-15
검증 기록은 당시 0.36 계열에 대한 이력이며 현재 검증 결과와 구분한다.

## 동일 내용 후보 조회

`resource_duplicate_candidates`는 선택된 컨테이너의 관찰된 파일을 기준으로 같은
SHA-256 관찰값을 가진 색인 후보를 반환하는 읽기 전용 도구이다. 응답의 `next`를
그대로 전달하여 페이지를 이어 읽으며 빈 페이지가 마지막 페이지라는 보장은 없다.
색인의 전체 범위와 현재 바이트의 일치는 확인되지 않으며, 이 응답은 삭제 또는
물리적 중복 제거의 승인이 아니다. 자세한 범위는 자원 저장소 연결 문서를 따른다.
