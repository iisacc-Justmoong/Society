# 에이전트 질문 화면의 네이티브 연결

Society macOS 데스크톱은 iiMultimodalAgent의 `UserQuestionsSheet.lvui`를 빌드 시
C++23으로 생성하고, iiGUI의 외부 표면에 마운트한다. 기존 MCP 질문 수신함은
모듈의 `NativeQuestionBridge`를 통해 같은 뷰모델에 연결한다. 질문 선택과 직접
입력, 전송·취소의 검증은 기존 모듈에 남아 있으며, 앱이 모듈들을 조합한다.
SDK 모듈 사이에 새로운 직접 의존성은 추가하지 않는다.

질문이 있고 창이 보일 때만 표면을 요청한다. 요청과 창 가시성 변경에 반응하며
대기 폴링을 추가하지 않는다. 요청이 빠르게 교체되면 이전 표면의 실제 종료를
기다린 뒤 새 표면을 열고, 오래된 종료 알림은 새 요청에 영향을 주지 않는다.
앱의 정상 종료도 표면 정리를 기다린다. 표면 연결이나 마운트에 실패하면 격리된
기존 QML 질문 화면을 사용한다. macOS 외 플랫폼은 아직 레거시 화면을 사용한다.
네이티브 모달 활성 수는 같은 창의 iiSDKCore 관측 상태로 공유하며 실제 표면
퇴역 뒤 해제한다. 창에 삽입되는 다른 화면은 이 이벤트로 모달보다 앞에 나오지
않도록 대기할 수 있다.

`tests/native-question-coordinator`는 취소·교체·재진입·실패와 비동기 종료를
가짜 표면으로 검사한다. `tests/native-question-presenter`는 모듈의 설치 스테이징
뷰를 AOT 생성하고 실제 브리지·iiGUI와 링크하며, 표시하지 않는 offscreen 창에서
진입 조건과 종료를 확인한다. 이 검사는 사용자 앱이나 GPU 창을 실행하지 않는다.
모듈 내부의 답변 검증과 생성 뷰 검사는 iiMultimodalAgent의
`docs/NativeQuestionView.md`에 별도로 기록한다.

iiGUI, 에이전트 뷰모델과 앱은 ABI가 같은 iiSDKCore로 빌드해야 한다. 같은 Core
버전 번호의 설치본이라도 바이너리 구성이 다를 수 있다. 사용 중인 Qt 6.8의 macOS
설정에서 최신 SDK에 없는 AGL 링크 항목은 앱 로컬 CMake 호환 처리로 제외한다.
생성기는 소비하는 LVUI 헤더와 같은 스테이징에서 선택한다. 다른 작업이 공유 빌드의
생성기를 갱신해도 이전 스테이징 헤더와 섞이지 않도록 소비자 구성에서 경로를 지정한다.

2026-11-14 macOS 빌드에서 Society 앱과 번들 정적 검사가 통과했으며, 번들의
에이전트·Core 바이너리 UUID가 검사한 스테이징과 일치했다. 런타임 검증 옵션은
끄고 앱과 기기 화면은 실행하지 않았다. 이 결과가 다른 플랫폼이나 실제 GPU 표시를
증명하는 것은 아니다.
