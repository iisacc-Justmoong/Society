# Society 장치 연결과 기능 상태 명세

## 목적과 적용 상태

이 문서는 Society 장치 화면과 장치 상태 모델의 **목표 제품 계약**이다. 기존 화면과
SDK가 이미 제공하는 범위는 [기존 구현과 이행 경계](#기존-구현과-이행-경계)에서
구분한다. 이 문서가 장치별 저장소·기능·작업·실행기 관측이 현재 구현되었다는 뜻은
아니다.

장치에 통신할 수 있다는 사실과 해당 장치가 특정 저장소를 읽거나 전송 작업을 수행할
수 있다는 사실은 다르다. 장치의 온라인 표시 하나를 모든 자원의 가용성이나 기능의
정상 동작으로 해석하지 않는다. 자원별 판본·사본·열기 가능성은
[자원 정체성과 보존 상태 명세](ResourceIdentityAndProtection.md)를 따른다.

## 장치 화면의 최소 정보

| 항목 | 사용자가 확인할 내용 | 구분할 경계 |
| --- | --- | --- |
| 연결 상태 | 현재 이 기기와 통신할 수 있는지, 연결 중인지 또는 확인할 수 없는지 | 발견, 인증된 통신과 저장소 가용성은 서로 다르다. |
| 마지막 응답 | 어느 연결이나 구성 요소가 언제 마지막으로 응답했는지 | 장치 응답과 저장소 검사·작업 갱신 시각은 각각 다를 수 있다. |
| 제공 저장소 | 장치가 제공하는 저장 공간·경로·볼륨과 각각의 상태 | 제공한다고 등록된 것과 현재 접근 가능한 것, 읽기와 쓰기는 다르다. |
| 기능별 상태 | 저장소 접근, 읽기·쓰기, 업로드·다운로드 등 각 기능의 상태 | 기능 지원, 권한, 현재 사용 가능성과 최근 실행 결과를 분리한다. |
| 진행 작업 | 이 장치가 실행하거나 이 장치를 대상으로 하는 작업의 상태 | 실행 기기, 출발·도착 위치와 작업 판본을 구분한다. |
| 연결된 실행기 | 연결된 전문 앱 또는 실행 계층과 그 상태 | 설치됨, 실행 중, 연결됨과 특정 기능을 수행할 수 있음은 다르다. |

장치·저장소·기능·실행기·작업은 각각의 식별자와 관찰 범위를 가진다. 기기 이름,
네트워크 주소, 표시 경로가 바뀌어도 이를 동일한 장치나 자원으로 확인할 수 있는
계약을 사용한다. 이름이나 주소가 같다는 사실만으로 서로 다른 장치·저장소를 합치지
않는다. 연결이 다시 만들어질 때는 이전 연결의 늦은 결과가 새 연결의 상태를 덮어쓰지
않도록 연결 문맥을 구분한다.

## 연결 상태와 마지막 응답

장치 연결은 적어도 **연결 중**, **통신 가능**, **연결 끊김**과 **미확인**을 구분한다.
연결 정보가 아직 없거나 오래되었다는 것만으로 장치 전원이 꺼졌다고 단정하지 않는다.
발견된 네트워크 후보나 등록된 장치 목록은 인증된 세션의 응답 또는 실제 파일 접근
권한과 같지 않다. `통신 가능`은 확인된 통신 경로의 최근 관찰을 뜻하며, 다음 요청의
성공까지 보장하지 않는다.

마지막 응답에는 응답한 대상·관찰 주체·시각과 알 수 있는 연결 범위를 함께 둔다.
다른 장치의 시계가 다르거나 역행할 수 있으므로 상대 기기 시각만으로 현재성이나
사건 순서를 확정하지 않는다. 최신 응답을 관찰한 뒤 정해진 확인 정책을 지나면 그
사실을 나타내고, 확인되지 않은 현재 상태는 미확인으로 표시한다. 응답이 오지 않아
연결이 끊겼다고 판단한 시점과 마지막으로 성공한 응답 시각도 구별한다.

장치의 heartbeat가 갱신되더라도 그때마다 외장 디스크나 각 기능을 실제로 검사한
것은 아닐 수 있다. 연결·저장소·기능·작업·실행기의 마지막 관찰 시각과 출처는 따로
관리한다. 최근 연결 응답으로 예전 저장소 검사 결과를 새로 확인한 것처럼 바꾸지
않는다. 관찰 시각을 제공하지 않는 정보는 시각 미확인으로 남긴다.

## 제공 저장소와 기능

장치가 제공하는 저장소마다 논리 저장 공간 및 제공자·기기와의 관계, 표시 경로 또는
볼륨, 확인 가능한 실제 접근 위치, 현재 관측 상태와 마지막 검사를 구분한다. 네트워크
저장소나 Cloud에는 해당 제공자의 locator를 사용하며, 다른 운영체제의 로컬 경로가
모든 기기에서 유효하다고 가정하지 않는다. 저장소의 이름·경로 변경이나 장치 연결이
자원 ID와 내용 판본을 바꾸지는 않는다.

각 저장소에는 해당 관찰 범위에서 **접근 가능**, **연결 또는 볼륨 분리**, **권한 부족**,
**오류**, **미확인** 등을 표현할 수 있어야 한다. 실제로 분리를 관측하지 못했다면
장치 통신이 끊겼다는 이유만으로 볼륨이 분리되었다고 표시하지 않는다. 이전에 성공한
확인 사실은 그 시각과 함께 유지하되, 현재 접근 가능성은 별도로 표시한다.

기능별로 지원 여부, 설정·권한, 최근 관찰된 사용 가능성과 오류를 구분한다. 예를 들어
저장소의 목록 조회는 가능하지만 특정 파일의 읽기가 거부되거나 전송 수신은 가능하나
전송 송신은 권한이 부족할 수 있다. 저장소가 보인다는 사실만으로 모든 경로·판본의
원본이 보유되어 있거나 읽기·쓰기·전송이 성공한다고 주장하지 않는다. 실제 동작을
요청할 때는 해당 주체, 대상 자원·판본·위치와 현재 권한을 다시 확인한다.

기능 상태 조회는 가능한 한 기존 관측과 제한된 비파괴 확인을 사용한다. 목록을 보기
위해 사용자 파일을 수정하거나 외부 장치를 자동 마운트하지 않는다. 제공자가 특정
상태를 관찰할 수 없으면 성공이나 실패를 만들어 내지 않고 미확인으로 둔다.

## 작업과 연결된 실행기

진행 작업에는 공통 작업 ID, 종류, 대상 자원·판본, 현재 단계·상태와 마지막 갱신을
사용 가능한 범위에서 표시한다. 이 장치가 작업을 **실행**하는지, 입력을 제공하는지,
결과를 받는지 구분한다. 장치 연결이 끊겼다는 사실만으로 원격 작업이 실제로 중단되거나
실패했다고 단정하지 않는다. 마지막으로 관찰한 작업 상태와 현재 상태 미확인을 함께
보여 주고, 재연결 후 작업 소유자의 상태를 다시 확인한다. 작업 수명·진행률·취소·
재시도는 [공통 작업 모델](JobsAndOperations.md)을 따른다.

연결된 실행기는 전문 앱, 앱이 제공하는 실행 계층 또는 작업을 수행하는 서비스처럼
실제 연결과 기능 범위를 식별할 수 있는 대상을 뜻한다. 실행기마다 식별자·종류,
어느 장치에 속하는지, 연결 또는 관찰 상태, 마지막 응답과 확인 가능한 기능을
구분한다. 하나의 앱에 실행기가 여러 개일 수 있으며, 알려지지 않은 실행기·버전·
기능을 화면 데이터로 만들어 내지 않는다.

앱이 장치에 설치되어 있다는 것은 실행 중이라는 뜻이 아니고, 실행 중이라는 것도
Society와 연결되었거나 특정 작업을 실행할 준비가 되었다는 뜻이 아니다. 반대로
앱의 창이 보이지 않아도 해당 실행 계층이 별도로 연결되어 있을 수 있다. 원격 실행이나
앱 제어 권한은 장치 연결 또는 목록 표시만으로 부여되지 않는다.

## 예시: 온라인 장치와 분리된 외장 디스크

다음은 설명을 위한 가상 상태다.

| 항목 | 예시 |
| --- | --- |
| Mac Studio 연결 | 인증된 통신 가능. 마지막 응답은 최근에 확인했다. |
| 내장 저장소 | 해당 저장소의 마지막 검사에서 접근 가능으로 확인했다. |
| 외장 디스크 | 장치는 응답하지만 디스크가 분리된 것을 확인했다. 해당 디스크의 원본을 지금 읽을 수 없다. |
| 전송 작업 | 외장 디스크의 원본을 기다리는 작업은 저장소 접근 대기 또는 실패 사유를 표시한다. |
| 전문 앱·실행기 | 실제 연결된 것으로 관찰된 실행기만 별도로 표시한다. 앱 설치 여부만으로 연결되었다고 적지 않는다. |

이 경우 장치가 온라인이라는 표시를 유지하면서도 외장 디스크와 관련 파일의 접근
불가를 명확히 보여 준다. 다른 저장소의 가용성까지 함께 실패로 만들지 않는다.
다른 기기에 해당 판본의 원본이 있는지 여부는 사본 기록과 실제 접근 상태로 따로
판단하며, 프리뷰가 있다는 사실만으로 원본을 열 수 있다고 표시하지 않는다.

## 표시·관찰과 권한

장치 목록은 연결 상태와 마지막 응답을 먼저 보여 주고, 선택한 장치의 상세에서 제공
저장소, 기능별 상태, 진행 작업과 연결된 실행기를 각각 확인할 수 있어야 한다. 각
상태에는 필요한 경우 관측 시각과 실패 이유를 함께 보여 주며, 색상 점 하나로 모든
상태를 요약하지 않는다. 목록과 상세 정보는 공통 상태를 관찰하며 화면을 닫는 것만으로
전송이나 검사가 취소되지 않는다.

장치의 상태·경로·작업·실행기 정보는 이를 조회할 권한이 있는 주체에게만 제공한다.
기존 인증·페어링과 저장소 접근 경계를 유지하며, discovery 정보나 캐시된 상태로
권한을 부여하지 않는다. 상태 표시나 색인 결과가 실제 파일 접근 승인과 무결성 검증을
대체하지 않는다.

연결 재설정·계정 또는 저장소 변경 뒤에는 이전 문맥의 늦은 결과를 새 장치 상태에
적용하지 않는다. 관측이 부분적이거나 갱신에 실패하면 해당 범위를 밝히고 나머지
기능의 확인 결과까지 임의로 지우지 않는다. 실시간 구독에서 중간 상태가 누락될 수
있다면 현재 스냅샷을 다시 조회해 복구한다.

## 기존 구현과 이행 경계

- Society의 Environment는 계정 범위의 장치 목록과 현재 장치, 일부 연결·공유
  컨테이너 상태 및 장치 추가·Browse 진입을 제공한다. 현재 화면이 이 명세의 장치별
  저장소·기능·마지막 응답·작업·실행기를 모두 관찰한다는 뜻은 아니다.
  [Environment 문서](Environment.md), [페어링 문서](Pairing.md)
- 앱 목록의 로컬 설치 확인과 별도의 원격 앱 재고는 실행기 연결 상태의 증거가 아니다.
  원격 장치에 실제로 어떤 앱이 설치·실행되는지는 제공받고 확인한 범위에서만 표시한다.
  [Environment 데이터 경계](Environment.md#data-boundaries)
- iiSocietyHelper Monitoring은 선택한 **로컬 컨테이너**의 영역 가용성·완전성,
  inventory와 데몬 heartbeat를 구분한다. 로컬 파일 기반 상태 채널이며 장치 간 인증된
  네트워크 연결이나 원격 볼륨별 기능 상태를 대체하지 않는다. heartbeat는 마지막 검사
  스냅샷을 재게시할 수 있고 구독은 heartbeat만의 변화를 전달하지 않을 수 있다.
  [Monitoring 프로토콜](../../../SDK/iiSocietyHelper/docs/Monitoring/Protocol.md)
- 기존 동기화는 호스트 연결과 전송 상태를 제공하지만, 집계형 완료 상태 하나로 각
  장치의 모든 자원·저장소·작업을 대신하지 않는다. 네트워크 승인과 저장소 검증은
  기존 [동기화 계약](Synchronization.md)을 유지한다.

구현 시 기존 SDK의 발견·인증·동기화·로컬 관측 계층을 각 책임에 맞게 연결하고,
부족한 장치별 관찰과 실행기 인터페이스를 정의한다. 비 GUI 데이터와 작업 소유권이
화면 수명에 종속되지 않게 하며, 제공자가 없는 상태는 미구현 또는 미확인으로 남긴다.

## 구현 시 수용 검증

1. 장치는 통신 가능하지만 외장 디스크가 분리된 경우, 장치 연결은 유지하고 해당
   저장소·원본 접근만 불가로 표시한다. 별도 내장 저장소의 상태는 보존한다.
2. 장치와 연결이 끊긴 경우 실제 디스크 분리 여부를 추측하지 않고 마지막 저장소
   관찰 시각과 현재 미확인을 구분한다.
3. heartbeat만 갱신되고 저장소 검사가 갱신되지 않아도 예전 검사 시각이나 접근
   결과를 새로운 검사로 표시하지 않는다.
4. 읽기·쓰기·송신·수신 권한이나 기능이 일부만 실패하면 영향을 받는 기능과 이유를
   구분한다. 권한이 없는 주체는 경로·작업 상세를 조회할 수 없다.
5. 앱이 설치만 되었거나 실행 중이지만 연결되지 않은 경우, 연결된 실행기로 표시하지
   않는다. 실제 연결된 실행기 여러 개는 각각 식별하고 상태를 관찰한다.
6. 장치에서 진행 중인 작업과 이 장치를 출발지·목적지로 사용하는 작업을 구분한다.
   연결 중단은 원격 작업의 자동 실패로 단정하지 않으며 재연결 후 상태를 확인한다.
7. 계정 전환·재페어링·연결 재설정 뒤 도착한 이전 관찰 결과가 새 문맥의 장치,
   저장소·실행기 상태를 덮어쓰지 않는다.
8. 부분 목록·느린 파일 시스템·오래된 상태·지원하지 않는 공급자에서 현재성을
   추측하지 않고 미확인 또는 불완전 범위를 표시한다.
9. 장치 목록과 상세 화면을 열고 닫는 것만으로 파일을 수정하거나 볼륨을 마운트하거나
   진행 작업을 취소하지 않는다.
