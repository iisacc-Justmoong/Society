# 계정이 소유하는 라이선스 관리와 앱 실행 허가

Society는 `AccountSession`의 iiAccountManager를 보유한다. iiAccountManager가
`unique_ptr<LicenseManager>`로 iiLicenseManager의 구현과 상태를 내부 소유한다.
두 SDK를 나란히 링크하거나 외부 라이선스 관리자를 계정에 주입하지 않는다.
Society의 빌드·실행 의존성에는 별도 iiLicenseManager 모듈이 없다.

`ensureLicenses()`는 보안 저장소의 계정·기기별 토큰을 먼저 확인한다.
서명·발급자·대상·계정·기기·제품·만료가 유효하면 네트워크 없이 허용한다.
토큰이 없거나 사용할 수 없을 때 인증된 `accountLicenses` 요청으로 갱신한다.
화면 진입과 앱 허가 요청은 이 경로를 사용한다. 사용자의 Refresh는 서버 결과로
기존 상태를 교체한다. 정상적인 미보유 응답도 서명되며 이전 허가를 덮어쓴다.

서버 서명 토큰의 기본 수명은 24시간이다. 세션과 제품 만료가 상한이다.
로그아웃 시 계정 내부 상태와 보안 저장소 토큰을 삭제한다. 오프라인 상태의
원격 폐기는 다음 명시 갱신 또는 만료 때 반영된다.

데스크톱의 SocietyDaemon은 동기화 소유권과 별도로 로컬 허가 서비스를 준비한다.
`127.0.0.1:49627/v1/authorize`와 같은 사용자 Unix 소켓에서 앱의 실행 허가를 처리한다.
요청마다 보호된 계정 저장소에서 현재 세션을 다시 복원하므로 실행 중 Society 창에
의존하지 않으며, 로그아웃이 저장된 뒤 시작한 새 요청은 이전 계정을 재사용하지 않는다.
Congregation·Dreamscapes·Vincent의 등록 제품/앱 조합만 받으며 요청 계정과
기기가 Society와 같아야 한다. 응답은 요청 ID, 허가, 서명 토큰, 만료를 포함한다.
브라우저 Origin, 잘못된 Host, 과대 요청, 중복 길이·전송 헤더는 거부한다.
외부 네트워크에 수신하지 않으며 계정 쿠키와 온라인 세션 토큰을 반환하지 않는다.
소비 앱도 서명을 검증해야 한다. 로컬의 임의 응답은 허가 근거가 아니다.

Environment → Apps에는 검증된 라이선스 보유 여부와 연결된 앱/브라우저를 표시한다.
제품은 설치 여부와 라이선스 상태를 구분하며, 현재 세션을 임의 해제하지 않는다.
연결 해제는 계정 서버의 공통 레지스트리를 사용한다.

`SocietyAccountTests::societyMountsAccountLicenseInventory`는 내부 관리자 소유,
로컬 토큰 재사용 시 서버 요청 0건, 실제 HTTP 허가, 다른 기기 및 브라우저 요청
거부, 미보유·위조 주체·로그아웃과 연결 해제를 검사한다. 다른 플랫폼의 소스
이식과 해당 플랫폼에서 두 앱을 연결한 실제 실행 검증은 구분한다.

Dreamscapes와 Congregation은 시작 시 서명 허가를 확인하고 그 실행에 한해 결과를
유지한다. 실행 중 데몬이 종료되거나 토큰이 만료되어도 편집을 중단하지 않는다.
다음 실행에는 현재 계정과 만료되지 않은 서명 허가가 다시 필요하다.

## 통합 검사 준비 조건

계정 통합 검사에서 전송 연결과 호스트 서비스 준비를 구분한다. 원격 생성 RPC는
네임스페이스 바인딩이 완료된 뒤 전송한다. 파일 잠금 충돌은 SDK가 같은 요청
안에서 재시도하므로 연결 검사도 즉시 오류 문구를 기대하지 않고 인증 유지와
잠금 해제 후 완료를 확인한다. 파일 실체화는 최대 30초, 별도 NAS 프로세스의 최초 바인딩은 최대 60초로 한정하며, 여러 실제 동기화 시나리오를 포함하는 전체 검사 실행 제한은 180~240초로 설정한다.

## 동일 사용자 로컬 계정 채널

Society는 macOS/Linux에서 현재 OS 사용자만 접근할 수 있는 전용 디렉터리의 Unix 소켓을
열고 연결자의 peer credential을 확인한다. 등록된 제품 ID와 앱 ID, 현재 기기 ID, 요청 ID가
일치할 때 현재 계정의 서명된 제품 라이선스를 반환한다. 비밀번호·서버 쿠키·온라인 Bearer는
전달하지 않는다. 제품은 자체적으로 서명과 기기·제품·만료를 검증해야 한다. 같은 OS 사용자
안에서 서로 다른 앱의 코드 서명을 구분하는 기능은 없다. 구형 TCP 브로커는 기존 세션 주체
검사를 유지하며 자동 로그인용으로 사용하지 않는다. Windows/iOS의 로컬 채널은 미지원이다.
일반 `SocietySession`은 계속 갱신할 수 있지만 두 제품은 첫 승인 후 세션을 종료하여
현재 실행의 허가를 유지한다. 승인 전 오류나 위조 응답은 허가하지 않는다.

`Society.Account` 로컬 fixture는 등록 제품의 같은 사용자 요청과 기기 결합을 검사한다.
실제 설치본의 자동 로그인과 운영 라이선스 보유 여부는 별도 검증이다.

빌드 의존성으로 사용되는 Society 달력은 iiCalendar의 현재 연결 주입 API에 맞춰 앱이 iiFileProvider를 통해 SQLite 연결을 열고 소유한다. 기존 일정 저장 경로와 이벤트 모델은 유지한다.
달력 및 드라이브 회귀 검사의 임시 작업 데이터는 `resources/` 아래에 생성하고 검사 후 정리한다.

## 로컬 원격 기능 중계

Society 창의 계정 객체는 별도로 `iiSocietyHelper::LocalService`를 시작한다.
현재 로그인과 서명된 제품별 라이선스가 유효한 경우에만 같은 사용자 프로세스의
파일 전송·동기화·원격 생성 요청을 처리하며, 연결 중 계정이나 권한이 바뀌면 닫는다.
이 서비스의 배치만으로 Dreamscapes 연결이나 실제 운영 활성화가 검증되는 것은 아니다.

로컬 브로커의 제품 업데이트 요청은 현재 기기와 제품 권한을 확인한 뒤 Society의
`AccountManager`로 서버에 전달한다. 응답 전 계정 바인딩과 권한을 다시 확인하며,
로그인 쿠키와 서버 자격 증명은 제품에 전달하지 않는다. 제품 측 업데이트 피드 연결과
실제 서명된 릴리스가 준비되기 전에는 업데이트 기능이 완성된 것으로 취급하지 않는다.

# 데몬 기반 앱 실행 허가

데스크톱의 앱 라이선스 브로커는 Society 창이 아닌 SocietyDaemon의 수명을 따른다.
각 새 요청은 보호된 계정 저장소에서 현재 세션을 복원한 뒤 기기와 제품에 묶인
서명 허가를 검증한다. 복원 실패·로그아웃·위조·미보유는 새 실행을 허가하지 않는다.
사용자에게 이미 허가된 앱의 현재 실행을 데몬 연결 변화로 중단하지 않는다.
Society 창은 로그인·로그아웃을 제공하며 실행 허가를 제공하기 위해 열려 있을 필요가 없다.
기본 로컬 소켓의 데몬이 꺼져 있으면 클라이언트가 라이선스 전용 데몬을 창 없이
기동한다. 기동 실패 또는 계정·서명 검증 실패는 새 실행을 허가하지 않는다.

macOS 데몬은 `QCoreApplication`만 사용한다. iiAccountManager의 Keychain 완료
신호는 Qt 이벤트 큐에서 처리하므로 GUI의 Cocoa 이벤트 루프를 기다리지 않는다.
저장된 서명 허가를 먼저 검증하고 사용할 수 없으면 인증된 서버에서 갱신한다.
헤드리스 저장소와 서명 라이선스의 오프라인 재사용은 별도 합성 계정 테스트로
검사하며, 운영 계정의 실제 허가는 설치된 앱에서 별도로 확인한다.
