# Society 판본·휴지통·복제·백업 명세

## 목적과 적용 상태

이 문서는 네 기능의 사용자 기대와 데이터 보존 경계를 정의하는 **목표 제품 계약**이다.
기존 Deleted, 동기화 복구 기록과 ObjectStore 이력의 현재 범위는
[기존 구현과 이행 경계](#기존-구현과-이행-경계)에 구분한다. 이 명세는 독립 백업과
시점 복구가 이미 구현되었거나 사용자의 데이터가 백업되었다는 뜻이 아니다.

| 기능 | 사용자가 기대하는 결과 | 이 기능만으로 보장하지 않는 것 |
| --- | --- | --- |
| 내용 판본 | 이전 작업 내용으로 돌아간다. | 삭제된 자원의 복원, 다른 기기의 사본 또는 독립 백업 |
| 휴지통 | 삭제한 자원을 복원한다. | 모든 과거 내용 판본이나 독립된 시점 복구 지점 |
| 복제 | 여러 위치에서 같은 자원의 특정 판본을 사용한다. | 삭제로부터 독립된 보존, 이전 시점 전체의 복구 |
| 백업 | 별도 보존 정책의 복구 지점으로 되돌린다. | 현재 모든 기기가 최신이라는 것, 실제 복구 시험이 성공했다는 것 |

네 기능의 기록과 상태는 별도로 조회한다. 자원 ID·내용 판본·물리적 위치와 세 가지
저장 완료 경계는 [자원 정체성 명세](ResourceIdentityAndProtection.md)를 따른다.

## 내용 판본

내용 판본은 자원의 특정한 확정 내용을 가리킨다. 사용자는 보존된 이전 판본의 내용과
그 시점·출처를 확인하고, 해당 바이트에 실제 접근할 수 있을 때 이전 내용으로 복원할
수 있어야 한다. 판본의 이력이나 해시만 존재한다는 사실은 이전 바이트가 여전히
보관되어 있다는 뜻이 아니다. 내용이 누락되었거나 보존 여부를 확인하지 못하면 복원
가능하다고 표시하지 않는다.

이전 내용으로 돌아가는 작업은 자원 ID와 기존 판본 이력을 유지한다. 현재 내용에
변화가 생기면 선택한 이전 내용을 바탕으로 **새 내용 판본**을 확정하며, 과거 기록을
수정하거나 이력의 시계를 되돌리지 않는다. 작업 사본이나 현재 확정 판본이 달라진
경우에는 기준 판본을 확인하고 충돌을 보존한다. 고정 판본을 사용하는 릴리스·게시물이
복원 작업만으로 조용히 바뀌지 않게 한다.

판본별 내용의 보존 기간과 실제 위치는 해당 정책과 관찰에 따른다. 모든 판본이
무기한 복원 가능하다거나, 같은 저장소 안의 이력이 별도 재해 복구 사본이라고 가정하지
않는다. 메타데이터 변경과 내용 변경도 별도의 이력으로 구분한다.

## 휴지통

휴지통은 사용자가 관리 범위 안에서 삭제한 자원을 복원하는 기능이다. 삭제 대상이
자원 전체인지, 프로젝트 관계만 제거하는지, 한 위치의 로컬 사본을 비우는지 명확히
구분한다. 프로젝트에서 참조를 제거하거나 오프라인 사본을 해제한 것만으로 원래
자원을 삭제했다고 표시하지 않는다.

삭제된 항목에는 확인 가능한 자원 ID, 삭제 시각, 원래 위치 또는 복원 대상, 삭제
범위와 복원 가능 상태를 연결한다. 복원할 때 이전 위치가 이미 사용 중이면 기존
파일을 조용히 덮어쓰지 않고 대상 선택 또는 충돌 처리로 보존한다. 자원의 정체성과
연결을 복원할 수 있는 정보가 남아 있다면 동일 자원으로 복구하며, 누락된 정보나
더 이상 확인할 수 없는 권한을 만들어 내지 않는다.

휴지통의 보존 기간, 비우기 및 기기별 적용 범위는 사용자에게 표시한다. 휴지통에
있다는 사실만으로 모든 과거 판본이나 다른 장애 영역의 사본이 있음을 주장하지
않는다. 사진 등 별도 플랫폼 제공자의 삭제·복원 정책은 해당 제공자의 실제 계약을
구분해 표시한다.

## 복제

복제는 같은 자원의 지정 내용 판본을 다른 위치에 배치·검증하고 사용할 수 있게 하는
기능이다. 어느 판본이 어느 위치에 있는지, 전송·검증·현재 접근 가능 상태가 어떤지
각각 표시한다. 원본과 다른 위치에 파일이 하나 더 보인다는 사실이나 프리뷰만으로
원본의 최신 판본이 전송·검증되었다고 판단하지 않는다.

일반 동기화 복제본은 해당 범위의 변경과 삭제를 전파받을 수 있다. 따라서 복제본은
사용성을 위한 사본이지만, 독립된 보존 정책과 복구 지점이 확인되지 않았다면 백업으로
표시하지 않는다. 같은 물리 볼륨이나 동일한 장애 영역을 공유하는 사본은 그 장애에
함께 영향을 받을 수 있다는 정보를 숨기지 않는다.

## 백업과 복구 지점

백업은 복제와 별개인 **보존 정책** 아래 선택한 범위의 내용을 복구 지점으로 남기는
기능이다. 복구 지점에는 적어도 식별자, 생성 시각, 대상 범위, 포함된 자원과 판본,
실제 보관 위치, 보존 정책과 알려진 검증 결과를 연결한다. 복원에 필요한 내용 바이트가
포함되어 있는지, 메타데이터·관계·프로젝트 정의 등이 포함되는지도 범위로 밝힌다.
목록이나 해시만 있고 원본 바이트가 없는 기록을 복구 가능한 백업으로 표시하지 않는다.

복구 지점이 여러 파일을 같은 시점의 일관된 스냅샷으로 보장하는지, 파일별로 얻은
상태인지 구분한다. 열려 있는 데이터베이스나 여러 파일이 함께 이루는 문서는 저장자
또는 포맷이 제공하는 일관된 스냅샷·백업 계약이 필요하다. 그런 보장이 없으면 전체가
같은 시점으로 복구된다고 표시하지 않는다.

복구 지점의 생성 완료, 저장된 바이트의 무결성 검증, 실제 복원 시험은 서로 다른
사실이다. 마지막 검증과 복원 시험의 시각·범위·결과를 아는 경우 표시하고, 확인하지
않은 것은 미확인으로 둔다. 정책·대상·자원별 포함 여부와 보존 기간 또는 만료 조건을
표시하며, 지정되지 않은 무기한 보존을 만들어 내지 않는다.

백업의 별도 보존 정책은 일반 복제 삭제와 독립되어야 한다. 다만 같은 볼륨, 동일한
저장 서비스 또는 같은 관리 권한을 공유하는 경우 장애나 손상의 위험도 공유할 수 있다.
하드 링크나 같은 물리 블록을 사용했다는 사실만으로 독립된 장애 영역이나 변경으로부터의
불변성을 보장하지 않는다. 바이트를 중복 제거해 공유할 경우에도 유효한 복구 지점이
참조하는 내용을 동기화 정리나 수거 작업이 제거하지 않도록 보호한다.

## 삭제 전파와 복구 지점의 기본 정책

**기본 목표 정책: 자원의 동기화된 삭제는 일반 동기화 대상에는 적용하되, 기존 백업
복구 지점을 즉시 삭제하지 않는다.** 백업 복구 지점은 그 복구 지점에 적용되는 별도
보존 정책에 따라 유지한다. 이는 명세상의 목표이며 현재 모든 저장소가 이를 구현하거나
검증했다는 뜻이 아니다.

| 동작 | 일반 동기화 대상 | 기존 백업 복구 지점 |
| --- | --- | --- |
| 동기화 범위의 자원 삭제 | 삭제 기록을 허가된 동기화 범위에 전파한다. 오프라인 기기는 재연결 후 처리한다. | 삭제 이벤트만으로 즉시 제거하지 않는다. |
| 휴지통 비우기 또는 항목 제거 | 선택한 휴지통 항목과 명시된 범위에 적용한다. 다른 위치의 처리 여부는 따로 표시한다. | 휴지통 제거만으로 즉시 제거하지 않는다. |
| 한 기기의 로컬 사본 해제 | 선택한 위치의 사본 정책에 적용한다. 자원 전체 삭제와 구분한다. | 사본 해제만으로 즉시 제거하지 않는다. |
| 복구 지점 삭제 또는 보존 기간 만료 | 일반 자원·사본의 삭제 명령과는 별도다. | 해당 복구 지점의 정책 또는 권한 있는 명시적 삭제에 따라 처리한다. |

백업 보존 기간 만료, 사용자가 요청한 복구 지점 제거 또는 별도로 설정된 정책에 따른
정리는 동기화 삭제와 구별해 기록하고, 어떤 복구 지점과 바이트에 영향을 주는지
표시한다. 정책이 복구 지점의 조기 삭제를 허용하도록 달리 설정되어 있다면 그 범위와
조건을 숨기지 않는다. 같은 저장소에서 백업과 일반 사본이 내부 데이터를 공유하더라도
삭제 전파·동기화 정리·참조 수거가 유효한 복구 지점을 훼손하지 않도록 한다.

장치가 오프라인이면 삭제가 아직 전파되지 않은 사본과 이미 처리한 사본을 구분한다.
오래된 오프라인 사본이 재연결됐다는 이유만으로 삭제된 항목을 자동 부활시키지 않는다.
오프라인 편집과 삭제가 경합하면 내용을 버리지 않고 기준 판본과 충돌 정책에 따라
처리한다. 일반 삭제가 백업에 전파되었는지 여부를 확인할 수 없다면 보존 성공을
추측하지 않고 해당 복구 지점의 상태를 미확인으로 둔다.

## 복원과 사용자 화면

사용자는 자원 상세나 복구 화면에서 각 기능을 다른 경로로 확인할 수 있어야 한다.
내용 판본에서는 해당 판본의 내용 보유·복원 가능성, 휴지통에서는 삭제·복원 상태,
복제에서는 위치별 판본·접근·검증, 백업에서는 복구 지점·범위·정책·검증을 표시한다.
각 화면은 현재 상태와 마지막 확인 시각을 구분하며, 어떤 원본 또는 위치가 없으면
복원할 수 없는지 알린다.

백업 복원은 사용자가 선택한 복구 지점과 범위를 대상으로 한다. 기존 자원에 이전
내용을 반영하는 경우 현재 작업과 충돌을 확인하고 새 판본으로 확정하며, 별도 자원으로
복원할 때는 새 정체성과 출처를 구분한다. 여러 파일의 복원이 일부만 성공했다면
성공한 범위와 실패한 범위를 표시하고 전체 복구를 완료했다고 주장하지 않는다. 복구
지점에 포함되지 않은 프로젝트 관계나 권한까지 자동으로 복원했다고 가정하지 않는다.
복원·검증·재시도는 [공통 작업 모델](JobsAndOperations.md)의 작업 수명과 결과
계약을 따른다.

### 예시

이미지 `R`의 현재 판본 `C2`가 Mac과 랩탑에 복제되어 있고, 별도 백업 복구 지점에는
이전 판본 `C1`이 포함되어 있다고 하자. 사용자가 동기화 범위에서 `R`을 삭제하면 일반
사본은 각 기기의 삭제 정책에 따라 반영된다. 기존 백업의 `C1`은 그 복구 지점의 보존
기간 동안 유지된다. 휴지통에서 `R`을 되돌리는 것과 백업에서 `C1`을 복원하는 것은
서로 다른 작업이다. `C2`가 휴지통이나 다른 사본에 남아 있는지, `C1`의 백업이 실제로
검증되었는지에 따라 가능한 복구 방법을 따로 표시한다.

## 기존 구현과 이행 경계

- Society Files의 Deleted는 파일을 이동하고 원래 위치 또는 선택한 위치로 되돌리는
  기능을 제공한다. Deleted에서 항목을 제거하면 해당 파일 시스템 항목을 삭제하지만,
  이미 관리된 원본과 기록된 이력은 별도로 남을 수 있다. 관리되지 않은 기존 파일에
  보관본이 항상 있는 것은 아니다. [Files 문서](Files.md), [관리 저장소](ManagedStorage.md)
- Helper Sync는 삭제 기록과 교체·삭제된 일반 파일의 기기 로컬 recovery 자료를
  보존한다. 문서화된 recovery는 경로 기록과 하드 링크를 사용하는 파일 단위 복구이며,
  별도 장애 영역이나 여러 파일의 일관된 백업 복구 지점으로 취급하지 않는다.
  [동기화 문서](Synchronization.md)
- Helper의 Namespace 리비전 그래프는 메타데이터 이력이며 기본 로컬 투영이 모든 과거
  바이트를 보유하지 않는다. 일부 제공자에 특정 버전을 별도로 배치·검증할 수 있다는
  사실만으로 자동 백업 정책이나 모든 시점의 복원을 보장하지 않는다.
  [Namespace 계약](../../../SDK/iiSocietyHelper/docs/Sync/Namespace.md)
- iiFileProvider ObjectStore는 관리 대상의 원본·버전·이력을 제공한다. 이 이력이
  존재한다는 것만으로 모든 Society 파일이 관리 중이거나 별도 보존 정책의 백업이
  생성되었다는 뜻은 아니다. [ObjectStore 계약](../../../SDK/iiFileProvider/docs/OBJECT_STORE.md)

독립 백업 정책, 복구 지점의 보존·검증·정리와 삭제 전파 경계는 구현과 대상 플랫폼의
검증이 필요하다. 기존 삭제·복제·복구 자료를 소급해 백업으로 이름 붙이거나 사용자
데이터를 이동하지 않는다.

## 구현 시 수용 검증

1. 내용 판본, 휴지통, 복제, 백업에서 각각 다른 복구 목적과 실제 보유 상태를 표시한다.
   판본 이력만 있고 바이트가 없으면 해당 판본을 복원 가능으로 표시하지 않는다.
2. 이전 내용으로 복원해도 자원 ID와 기존 이력이 유지되고, 현재 작업과의 기준 판본
   충돌이 있으면 어느 쪽도 덮어쓰지 않는다.
3. 자원 삭제, 프로젝트 관계 제거, 한 기기의 사본 해제를 구분한다. 휴지통 복원 경로에
   다른 파일이 있어도 기존 파일을 덮어쓰지 않는다.
4. 동기화 삭제와 휴지통 비우기는 기본 정책에서 유효한 백업 복구 지점을 지우지 않는다.
   복구 지점은 별도 정책의 만료 또는 명시적 제거에서만 해당 정책대로 처리한다.
5. 일반 사본과 백업이 데이터 블록을 공유하더라도 삭제 전파나 수거 이후 유효한 복구
   지점의 내용을 읽고 무결성을 확인할 수 있다.
6. 오프라인 기기의 삭제 전파 대기와 오프라인 편집 충돌을 구분하고, 낡은 사본의
   재연결로 삭제된 자원이 자동 부활하지 않는다.
7. 백업 대상의 불완전한 캡처, 없는 바이트, 실패한 검증과 검증되지 않은 복원을 각각
   표시한다. 검증 완료와 복원 시험 완료를 같은 상태로 표현하지 않는다.
8. 동일 볼륨이나 제공자를 공유하는 사본의 위치와 장애 범위를 표시하며, 별도 장애
   영역에 있다고 추측하지 않는다.
9. 복구 지점에서 선택한 범위만 복원하고 부분 실패·충돌을 남긴다. 포함되지 않은
   프로젝트 관계, 릴리스·게시물 또는 권한을 조용히 바꾸지 않는다.
10. Deleted와 로컬 동기화 recovery 자료만 있는 기존 저장소를 독립 보존 정책의 백업이
    이미 설정된 것으로 표시하지 않는다.
