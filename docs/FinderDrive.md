# Finder drive for container packages

Society's `.societycontainer` directory package remains the authoritative storage location. On macOS 26 and later, the SDK's signed FSKit module projects the existing `Files/` directory as a separate filesystem named **Society**. Finder shows this mounted volume in Locations and its computer view. It is not a Finder favorite, symbolic link, copied disk image, or File Provider replica.

The other eight storage sections and application metadata retain their original paths. The public volume does not expose them. The original manifest UUID becomes the filesystem volume UUID. Reconnecting reuses an existing mount only when its filesystem type and source URL match the selected `.societycontainer` package.

At startup, the macOS app opens the saved `.societycontainer` package and connects the installed native adapter. `Reconnect` performs the same mount operation. Success requires both the native host's mount result and `QStorageInfo` to identify `societyfs` at the returned volume root. `Open in Finder` then opens that mounted root. A missing or disabled extension produces an actionable connection error without changing the source data or reverting to a disk image.

On macOS 27, the signed native host uses public FSKit mounting and DiskArbitration unmounting. macOS creates and manages the mount path under `/Volumes/`, while every stored file remains in the selected package. The host verifies the manifest UUID and mounted resource before reusing or unmounting a drive, including after the package is renamed. The host requires a matching `com.apple.developer.fskit.mount` provisioning profile. On macOS 26, the CLI adapter uses `<container>/.society-runtime/mounts/<container UUID>/Society` and requires ownership enabled on the container's host volume. Neither path creates an external data store.

Build the SDK with an Apple development signing identity and its developer team, following [the SDK directory-storage instructions](../../../SDK/iiSocietyContainer/docs/DirectoryStorage.md). Enable the Society module once in System Settings > General > Login Items & Extensions > File System Extensions. The app restores the mount when opened; the filesystem remains mounted after the app window closes. Removing or disabling an extension and reboot behavior must be verified separately when distributing a new signed build.

Validation uses the SDK's explicit `tests/native_directory_mount.py` integration test for an actual mount, Files-only enumeration, Unicode file CRUD, repeated reconnect, unmount/remount, original UUID preservation, and rejection of a plain folder. The app's ordinary-directory regression test continues to run without registering OS extensions. Native Finder and installed-app checks supplement those tests.
