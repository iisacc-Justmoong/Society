# Workspace 에이전트의 Society 도구 계약

Workspace 우측 패널은 백그라운드 iiMultimodalAgent 세션의 클라이언트다.
에이전트는 선택된 컨테이너에 한정된 디렉터리 조회, 자원 정보 조회,
파일 작업 제출·상태 조회와 모델 가져오기 제출 도구를 사용할 수 있다.
연결된 Society 창의 상태를 읽고 승인 후 섹션이나 디렉터리로 이동하거나
새로고침할 수도 있다. 창 조작은 데몬과 창에서 각각 컨테이너를 재확인한다.
파일 작업과 모델 가져오기는 기존 Society 데몬 및 iiSocietyContainer 작업을
사용하며, 접수 응답은 작업 완료가 아니다. 완료 여부는 작업 상태로 확인한다.

도구 선택은 iiDecision을 통과한다. 호스트 평가가 없을 때 iisaccson의
미보정 상대 추정으로 후보를 평가하며, 이는 도구 접근 권한이 아니다.
읽기 전용 조회를 제외한 조작은 실행할 도구 이름과 전체 인자, 대상
컨테이너를 기존 사용자 질문 화면에 표시하고 해당 호출에 대해서만
명시적 승인을 받는다. 응답이 없거나, 연결이 끊기거나, 취소되거나,
검토 내용을 안전하게 표시할 수 없으면 실행하지 않는다. 현재 질문 화면은
스크롤되지 않으므로 전체 검토 문구가 512자 또는 UTF-8 1,536바이트를
넘는 호출은 거부한다. 이 경우 인자를 나눌 수 있는 작업만 나누어 요청한다.

모든 데몬 요청은 세션이 시작된 컨테이너에 고정된다. 선택이 바뀌면 이전
세션은 취소되며, 이미 전송된 작업은 수신 여부가 불확실할 수 있으므로
자동으로 재전송하지 않는다. 모델의 추정, 도구 결과 또는 대화 내용은
사용자 승인을 대신하지 않는다. 호스트가 명시한 별도 평가 정책이 있으면
해당 정책을 사용하고 평가가 누락된 도구는 보류한다.

처음 연결하는 도구는 파일 내용 편집이나 임의의 셸 실행을 제공하지 않는다.
첨부 파일도 기존처럼 미지원이다. 파일 조회는 컨테이너 목록과 저장된 자원
정보에 한정되며, 선택한 모델이 도구 호출을 지원하지 않으면 오류를 표시한다.
모델 컨텍스트를 고려해 목록은 기본 5개, 최대 20개씩 페이지로 반환하고
큰 응답은 한 번에 생략하지 않고 더 작은 페이지를 요청하도록 오류를 반환한다.

macOS 본 앱 빌드는 질문 화면을 포함한 iiMultimodalAgent 패키지와 해당
LVUI·iiGUI 버전을 함께 사용해야 한다. iiLocalDiffusion 패키지에는
`NativeImageExecution`과 모델 패키징 역할 지정 API가 모두 있어야 하며,
iiVoiceOver도 에이전트 라이브러리가 요구하는 UTF-8 검증 심볼을 제공해야
한다. MLX 바이너리와 Metal 리소스는 같은 빌드의 쌍을 사용한다. 패키지
발견이나 빌드 성공만으로 모델 추론 또는 설치된 앱의 동작을 보증하지 않는다.

## 동일 내용 후보 조회

`resource_duplicate_candidates`는 선택된 컨테이너에 고정된 읽기 전용 도구이다.
관찰된 SHA-256이 같은 `Files`와 `Models`의 관리 자원을 페이지 단위로 찾는다.
현재 바이트 비교나 삭제 판단은 수행하지 않고, 색인 범위의 완전성은 알 수 없다.
빈 결과에도 다음 페이지가 있을 수 있으며 응답의 `next`를 그대로 전달한다.
각 페이지와 응답 크기는 제한되고 너무 큰 응답은 더 작은 `limit`으로 다시 요청한다.
경로가 매우 길어 `limit`이 1인 응답도 제한을 넘으면 CLI를 사용한다.

## 기존 색인 검색

`resource_search`는 컨테이너의 기존 텍스트·분류 색인이나 저장된 가상 디렉터리를
읽는다. 색인을 새로 만들지 않으며, 내용 임베딩 검색이나 전체 파일 범위의 완료를
주장하지 않는다. 검색 조건, 페이지·응답 제한과 cursor의 유효 범위는 자원 검색
계약을 따른다.

## 기록된 관계의 계보 조회

작업 공간 에이전트의 `resource_lineage`는 선택된 컨테이너의 `Files` 또는 `Models` 경로, 방향 `incoming`·`outgoing`·`both`, 깊이 1–3, 관계 수 1–20을 받아 명시적으로 기록된 관계를 읽는다. 응답이 에이전트의 8 KiB 상한을 넘으면 더 작은 관계 수로 다시 요청하거나 CLI를 사용한다. 등록되지 않은 외부 프로젝트와 파일 내부의 참조는 전체 조사되지 않으며, 응답의 `incomplete`, `truncated`, `reconciliationRequired`, `boundaryReached` 및 `unavailableProjects`를 함께 확인해야 한다. 빈 결과는 삭제 가능이나 복구 가능의 근거가 아니고 이 명령은 이동 복구나 파일 수정을 하지 않는다.

이 조회는 SDK의 관찰 전용 열기 경로를 사용한다. 선택 과정이나 다른 작업에서 이미 시작한 유지 관리는 별도로 계속될 수 있다.

## 정리 계획과 삭제 제한

`resource_cleanup_plan`은 파일의 마지막 관찰과 기록된 직접 관계를 바탕으로 정리 보류 사유를 반환한다. 이는 읽기 전용 검토 자료이며 승인이나 삭제 요청이 아니다. 현재 종속성 범위와 복구 가능성은 미확인이므로 `file_job_submit`의 `trash`, `remove` 및 Deleted로 향하는 `move`는 사용자 질문을 표시하기 전에 거부하고 `resource_cleanup_plan`을 안내한다. 다른 파일 작업은 기존 승인 절차를 따른다.

## 제한된 바이트 대조

`resource_compare_bytes`는 선택된 컨테이너의 `path`와 `otherPath`를 각각 최대 64 MiB로 제한해 별도로 캡처한 스냅샷을 비교한다. `comparison`이 `equal`이어도 두 원본의 공동 시점·현재 상태·삭제 가능성·복구 가능성을 보장하지 않으며 파일 내용을 변경하거나 중복 제거하지 않는다. 이미 진행 중인 비교가 있으면 새 요청은 거부된다.

## 텍스트 내용 의미 색인과 검색

Workspace 에이전트의 `resource_content_index`는 선택 컨테이너의 관찰된 텍스트 한 건과 명시한 로컬 임베딩 모델을 사용해 파생 벡터를 쓴다. 쓰기 도구이므로 기존 호출별 사용자 승인 정책을 따른다. `resource_content_search`는 같은 모델과 접두어의 벡터를 조회하는 읽기 도구이다. 컨테이너나 모델 서비스 선택이 바뀌면 이전 제공자를 취소하고 이전 요청의 결과를 다른 컨테이너에 전달하지 않는다.

관찰된 텍스트는 명시적으로 켠 정책으로 자동 색인할 수 있지만 외부 변경의 완전한 감지와 다른 미디어 형식은 아직 제공하지 않으며, 결과의 `completeness`는 `unknown`이다. 벡터 유사도와 빈 결과를 파일 동일성, 정사, 권한 또는 삭제 가능성으로 해석하지 않는다. 지원 형식, 크기, 모델 로딩, 임시 파일과 보안 경계는 `ResourceSearchAndViews.md`의 현재 구현을 따른다.

## 자동 내용 색인의 에이전트 정책

`resource_content_policy`는 선택된 컨테이너의 정책과 최근 작업 상태를 읽는다. `resource_content_policy_set`은 `enabled: true`, 설치된 임베딩 `model`, 선택적인 `documentPrefix`·`queryPrefix`로 자동 작업을 켜며 `enabled: false`로 끌 때는 모델과 접두어를 전달하지 않는다. 이 변경은 쓰기 도구이며 기존 호출별 사용자 승인과 선택된 컨테이너의 고정 검증을 거친다. 거부된 호출은 정책을 바꾸지 않는다.

자동 작업은 지원 텍스트를 관찰한 뒤 관리 저널에서 색인하며, 외부 변경의 완전한 감지는 보장하지 않는다. 상태의 `worker`는 최근 관찰값이며 `idle`은 전체 파일에 대한 완전성을 뜻하지 않는다. 자세한 대기열, 재시도, 임시 원문과 모델 공간의 제약은 `ResourceSearchAndViews.md`를 따른다.
