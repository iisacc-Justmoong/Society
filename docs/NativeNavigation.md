# Society navigation segment

The desktop navigation follows [Society's seven-item Figma segment](https://www.figma.com/design/vzGhdYpJ2GeyNfwXADJeAu/Society?node-id=739-15698): Environment, Tasks, Library, Space, Browse, People and Hosting, in that order. LVUI owns the segmented control, icon buttons, geometry and selection colors; Society supplies only destinations and the active selection. The Society accent is green.

Tasks opens the existing Tools view, Library opens Storage, and Browse opens the existing Browse view. The first segment opens the Workspace (Dashboard) containing Suggested and Recent. Hosting opens the existing environment hosting information. Space and People must not pretend an unimplemented service exists: their activation reports that the feature is not connected and preserves the current selection. The selection follows navigation initiated elsewhere in the application as well as a segment click.

`NativeNavigation.lvui` generates iiGUI widgets and `NativeNavigationViewModel` owns their destination requests and selected state. Six vector icons are the Figma exports of the corresponding LVUI icons; the Environment icon comes from the LVUI catalog. Hosting uses the purple 12 × 12 vector from the actual Figma instance, centered within its 16 × 16 server icon and 22 × 22 button. The remaining buttons use LVUI's 18 × 18 icon default. The group has no border or outside padding, and its buttons are separated by 2 px.

The existing application shell hosts the generated view through `NativeNavigationSurface` and iiGUI's `PaintView`; `QtPaintDevice` translates the resulting drawing commands to the existing window's surface. It does not introduce application-specific button or color tokens. Input is sent to iiGUI, and the host exposes the same seven named and selectable buttons to the platform accessibility interface. A queued destination request prevents a page change from reentering an active iiGUI input dispatch.

`LegacyNavigationBridge` connects this surface to the current shell without modifying the legacy QML view. It uses the existing toolbar viewport for placement and translates destination requests to the shell's existing navigation signals. The old segment group remains only as a hidden, disabled layout dependency of that shell; it cannot receive input or be presented by accessibility. The bridge is installed once per window and falls back to the old group if the LVUI surface cannot initialize. It follows external page changes, and resolves Hosting to the existing Environment overview after its asynchronous loader finishes. This bridge is temporary and should be removed when the surrounding shell has its own LVUI view.

Building the application requires an LVUI native package and an iiGUI package that includes `iiGUI/PaintView.h`. CMake defaults to the packages under `~/.local/SDK` and reports an explicit error if the selected iiGUI is too old. An alternate compatible package can be selected with `SOCIETY_NAV_IIGUI_PREFIX` and its `iiGUI_DIR`; `SOCIETY_NAV_LVUI_DIR` supplies the LVUI package hint. These navigation settings are separate from the existing native model chooser and file helper dependency settings. When changing a cached LVUI package, update `LVUI_DIR` as well.

The desktop segment is replaced as one unit. The existing mobile bottom navigation remains a separate layout. The rest of the Society shell still uses QML and LVRS; this change does not represent a complete application migration to LVUI. `Society.NativeNavigationViewModel`, `Society.NativeNavigationView`, and `Society.NativeNavigationSurface` cover destination mapping, generated controls and geometry, pointer delivery, rendering, keyboard focus and accessibility on isolated test surfaces. `Society.ToolbarSegmentAppearance` and `Society.TasksNavigation` cover the app shell's selection and routing. An installed application or a real OS window requires separate verification.
