# Files 관리

Society 컨테이너의 `Files`에는 `Documents`, `Audios`, `3D objects` 세 기본 디렉터리가 존재한다. 기존 컨테이너를 열어도 누락된 폴더가 추가되며 파일 위치는 유지한다. Files와 같은 계층의 `Society/Photos/`는 사진과 비디오를 함께 다루며 [기기 사진 보관함과 양방향으로 연결한다](Photos.md). 다른 폴더의 파일을 종류에 따라 이동하는 자동 분류는 수행하지 않는다.

Storage → Files와 Finder/파일 앱에는 같은 실제 디렉터리가 표시된다. 기본 폴더 자체는 삭제·이름 변경·이동할 수 없으며 내부 파일과 사용자 하위 폴더는 일반적으로 관리한다. 내부 파일은 폴더 간에 직접 이동할 수 있다. 기본 이름과 충돌하는 일반 파일 또는 링크가 있으면 덮어쓰지 않고 컨테이너 열기가 실패한다.

구조와 디렉터리 객체는 `iiSocietyContainer` 0.13.0의 `FileDirectory`·`FilesView`가 제공한다. Society는 LVRS 파일 그리드와 탐색 객체를 사용하고, Photos에는 네이티브 참조와 직접 저장한 프리뷰를 보여주는 전용 화면을 제공한다. SDK의 [Files 계약](../../../SDK/iiSocietyContainer/docs/Files.md)에 생성·보호·객체 API를 설명한다.

`iiSocietySync`는 기본 폴더를 없애는 원격 삭제 기록보다 디렉터리 유지 상태를 우선하고 새 버전으로 기록하여 재전송도 처리한다. 원격에서 기본 경로를 파일로 교체하려 하면 파일은 충돌 사본으로 보존한다. 최초 호스트 채택 시 기존 내용은 복구 디렉터리로 보관하고 기본 폴더 자체는 유지한다.

`Society.Drive`는 실제 Main/Storage에서 세 폴더의 표시·탐색과 Photos 전용 화면 진입을 검사한다. 사진·비디오 객체, 프리뷰와 네이티브 동작은 `Society.Photos`에서 별도로 검사한다. 기존 스크롤·선택 유지 테스트는 세 폴더가 포함된 목록으로 실행한다. OS 관리자 권한으로 원본을 직접 삭제하는 경우는 네이티브 파일 제공자 정책 밖이며 다음 정상 열기에서 폴더를 다시 만든다.
