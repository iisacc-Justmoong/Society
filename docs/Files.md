# Files 관리

Storage의 **Files 및 그 하위 폴더**는 [Figma의 본문 영역 39:1014](https://www.figma.com/design/vzGhdYpJ2GeyNfwXADJeAu/Society?node-id=39-1014)을
`FilesBrowser.qml`로 구현한다. Storage 사이드바는 기존 구성을 유지한다.
나머지 Storage 섹션은 기존 그리드·사진·모델 화면을 유지한다.
Storage 탭을 누르면 Overview 없이 Files 최상위 폴더를 바로 표시한다. 다른 영역이나
하위 폴더를 보고 있었더라도 Storage 탭을 다시 선택하면 Files 최상위로 이동한다.
특정 영역·폴더 바로가기의 목적지는 유지한다.

Files 툴바는 [Figma 39:1022](https://www.figma.com/design/vzGhdYpJ2GeyNfwXADJeAu/Society?node-id=39-1022)를
따른다. 왼쪽에 List/Grid 세그먼트와 Sort를 8px 간격으로 배치하고 오른쪽에 폭 205px의
Search Files를 둔다. 좁은 화면에서는 검색 폭만 줄이며 모든 컨트롤의 LVRS 기본 높이를
유지한다. 상단 경로 버튼은 제거하고 하단 경로 정보는 유지한다.

Storage 전체에서 Up·breadcrumb 표시줄을 제거한다. 영역 이동은 기존 사이드바·모바일
탐색 시트를 사용하며, 상위 폴더는 플랫폼의 뒤로 가기 단축키 또는 기존 모바일 가장자리
제스처로 이동한다. 모바일 Storage actions는 앱의 기존 상단 바로 옮겨 접근을 유지한다.

Files의 기본 화면은 LVRS Table이며 파일명·수정일·종류·크기를 표시한다. Table의
`rowHeight`, `rowHeights`, 헤더 높이, TableCellItem의 `cellHeight`는 오버라이드하지 않는다.
기본 행 24px, 헤더 25px와 ListItem.Navigation 기본 44px를 그대로 따른다.
Files 안에서만 List/Grid를 전환할 수 있고 검색과 정렬은 두 보기에 공통으로 적용한다.
좁은 화면에서는 상세 패널을 숨기고 표를 가로 스크롤하며 컨트롤 높이는 유지한다.

데이터는 기존 SDK `StorageDirectoryModel`에서 읽는다. 폴더를 우선 표시하고 열 제목·Sort
메뉴로 정렬하며 크기는 실제 바이트 수, 날짜는 실제 시각으로 비교한다. 단일 클릭은 선택,
더블 클릭·Enter·Open은 기존 SDK의 다운로드/열기 경로를 사용한다. 우클릭·길게 누르기와
복사·붙여넣기도 기존 FileActionMenu를 재사용한다. Reveal은 현재 폴더를 OS 파일 관리자로
연다. 변경된 목록에서도 선택 경로와 스크롤 위치를 유지하고 이동·검색 제외·삭제 시 선택을
해제한다. 예시 파일이나 기본 폴더를 생성하지 않는다.

상세 패널은 실제 수정일·크기·로컬/원격 상태를 표시한다. 생성일과 이미지 크기는 선택한
로컬 항목에 한해 GUI 어댑터 `DirectoryLocation.fileDetails()`에서 읽는다. 제공되지 않는
생성일은 `—`로 표시하고 PDF 페이지 수 등 읽지 않은 메타데이터는 만들지 않는다.
`Society.Gui`는 목록·검색·선택·열기·갱신·보기 전환과 LVRS 기본 높이를 검증한다.

파일 그리드의 하위 폴더는 폭과 높이가 같은 정사각형
클릭 영역을 사용한다. 폴더 프레임의 배경과 테두리는 기본·호버·누름·선택 상태에서
모두 표시하지 않는다. 하위 폴더의 선택은 이름의 강조색으로
구분한다. 일반 파일 카드의 높이와 갤러리의 정사각형 프리뷰는 기존 규칙을 유지한다.
`Society.Gui`는 여러 창 크기에서 폴더의 비율·투명도·테두리와 선택 후 키보드 열기를
검증한다. `Society.Drive`는 실제 Storage 탭의 Files 진입과 폴더 이동을 검증하고
`build/storage-files-entry/files.png`에 화면을 기록한다.

스토리지의 파일·생성 기록 목록은 백그라운드 조회를 계속하되, 같은 결과로 화면을
다시 만들지 않는다. SDK가 실제로 바뀐 행과 역할만 반영하며, 갱신 전후 선택 경로와
스크롤 위치를 유지한다. 최신순 화면의 끝을 보고 있더라도 새 항목 도착만으로 카메라를
이동하지 않는다. 최초 폴더 진입·정렬 변경 때만 초기 위치를 정하고, 삭제로 화면 범위가
줄어들면 유효한 끝 위치까지만 제한한다. `Society.Gui`와 `Society.Drive`가 이 동작을 검증한다.

파일 그리드, 모델 카드, 대시보드의 파일·생성 기록에서 우클릭하거나 터치로 길게 누르면
열기·폴더 보기·복사·경로 복사·붙여넣기·복제·이름 변경·공유·삭제 메뉴가 열린다.
macOS의 공유는 시스템 공유 선택기를 사용한다. 복사는 Finder와 호환되는 파일 URL을
클립보드에 넣으며, 붙여넣기는 대상 폴더의 빈 공간 메뉴 또는 파일 메뉴로 실행한다.
파일 그리드에 키보드 포커스가 있을 때 표준 복사·붙여넣기 단축키도 사용할 수 있다.

삭제는 다운로드·모델 검사·해시 계산·동기화 잠금을 기다리지 않고 `Deleted/`로 이름만
변경하여 이동한다. 다른 파일시스템으로의 복사로 대체하지 않는다. 복구하려면 Deleted에서
복사한 뒤 원하는 폴더에 붙여넣는다. Deleted 안에서는 파일 이름을 표시한 확인 시트를 거쳐
파일시스템에서 직접 영구 삭제한다. 블록·노드·모델 의존 관계를 탐색하지 않으며, 디렉터리는
하위 파일을 직접 제거한다. 호스트의 목록도 실제 경로를 우선하므로 재색인이 끝나기 전에
삭제가 반영된다. 동기화 기록 갱신은 이후 별도로 진행한다. 최상위 섹션
자체는 변경할 수 없다. 모델 패키지는 모든 하위 파일을 함께 다룬다. 복제 작업은 SDK
작업 스레드에서 수행하며 완료된 사본만 목록에 표시한다. 이름 충돌은 덮어쓰지 않는다.
복사·복제·공유·이름 변경은 선택한 파일·패키지에 한해 원본을 준비한 뒤 동작한다.
로컬 내용이 없는 원격 전용 항목의 삭제는 다운로드하지 않고 호스트에서 삭제하라는 오류를
즉시 표시한다. 메뉴를 여는 것만으로는 다운로드하지 않는다. SDK 계약은
[FileActions](../../../SDK/iiSocietyContainer/docs/FileActions.md)에 있다.

사진·비디오 화면은 같은 우클릭/길게 누르기 방식으로 열기·복사·복제·공유·삭제를 제공한다.
PhotoStore가 네이티브 원본과 다중 리소스를 처리하며, 복제는 별도 사진 ID를 만든다.
사진 삭제는 기존 기기 사진 보관함 삭제 경로를 사용하고 OS의 동의 절차를 따른다.
별칭이나 프리뷰만 복사·삭제하지 않는다.

`Society.Gui`는 실제 우클릭과 복사·복제·Deleted 이동 및 사용자 폴더 변경를 검사하고,
`Society.Photos`는 원본 바이트 내보내기와 다중 리소스 사진 복제·삭제를 검사한다.
사진 TLS 검사는 최초 동기화 신호가 아니라 사진 별칭의 실제 도착과 프리뷰 해시 일치를
확인한 뒤 원본 전송을 검사한다. 호스트의 인덱스 배치 게시와 파일 도착을 혼동하지 않는다.
공유 Qt를 사용하는 데스크톱 구성은 이전 앱 사본까지 포함하는 `build/` 전체 QML import
탐색을 생략하며 실제 QML 로딩은 앱·GUI 회귀 검사로 확인한다. 정적 모바일 구성은 유지한다.

Society의 `Files/`는 기본 제공 항목 없이 시작한다. 생성·열기·동기화·네이티브 파일 제공자
갱신으로 하위 폴더를 만들거나 복원하지 않는다. `Documents`, `Audios`, `3D objects`도
일반 사용자 이름으로 사용할 수 있으며 삭제·이름 변경·이동이 가능하다.

이전 버전에서 생성된 기본 폴더는 컨테이너를 최초 갱신할 때 비어 있는 경우에만 정리한다.
숨김 항목을 포함해 내용이 있거나 파일·링크인 경우에는 보존한다. 이전 완료를 매니페스트에
기록하므로 이후 사용자가 같은 이름으로 만든 빈 폴더는 그대로 유지한다.

Storage → Files와 Finder/파일 앱은 같은 사용자 항목을 표시한다. Files와 같은 계층의
`Society/Photos/`는 [사진과 비디오를 기기 보관함과 연결한다](Photos.md).
SDK의 [Files 계약](../../../SDK/iiSocietyContainer/docs/Files.md)에 생성·이전·조회 규칙을 설명한다.

`Society.Drive`는 새 Files 화면의 빈 상태, 사용자가 만든 폴더의 탐색과 삭제, Photos 전용
화면을 검사한다. `Society.Gui`는 이전 기본 이름의 삭제 메뉴와 삭제 후 미복구를 확인한다.
동기화·모델 가져오기·네트워크 목록 테스트도 기본 폴더가 없는 상태에서 실행한다.
