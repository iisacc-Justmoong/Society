# 사진 화면의 네이티브 연결

Society의 macOS·iOS 및 Windows 데스크톱 구성은 iiPhotoLibrary의 `PhotosView.lvui`와 C++ 프레젠테이션
모델을 기존 사진 영역의 iiGUI 표면에 장착한다. 기존 사진 서비스는 파일과
라이브러리의 권한·동기화·명령을 계속 소유한다. 새 화면을 기존 저장소에
접속시키기 위한 선택적 브리지는 같은 서비스 인스턴스를 사용한다.
저장소 화면이 실제로 열리고 사진 서비스가 제공될 때만 표면을 만들며, 다른
탭이나 숨겨진 사진 화면에서는 썸네일 우선순위를 비우고 표면을 퇴역한다.
서비스가 교체되면 이전 표면을 닫은 뒤 새 서비스와 모델을 연결한다.

`PhotoPreviewResolver`는 가시 뷰가 요청한 주소와 크기별로만 로드를 요청하고,
결과·무효화는 해당 미리보기를 관측하는 바인딩에 전달한다. 같은 미완료 요청은
합치며, 주소가 무효화된 뒤 도착한 이전 결과와 파괴된 뷰의 결과는 폐기한다.
로딩 중 무효화되면 기존 요청이 끝난 뒤에만 새 요청을 시작한다.
호스트가 캐시 항목 수와 래스터 바이트 한도를 명시한다. 관측 중이거나 로딩 중인
항목은 한도를 맞추기 위해 제거하지 않으며, 여유가 없으면 새 요청은 빈 결과로
남는다. 로더의 완료 콜백은 소유 스레드에서 호출해야 한다.

`PhotoPreviewLoader`는 호스트가 지정한 파일 크기와 원본 픽셀 한도 내의 로컬
이미지만 기존 백그라운드 실행기에 맡겨 디코딩한다. 동시에 실행할 요청과 대기열의
크기도 호스트가 지정하며 대기열이 가득 찬 요청은 실패로 돌려준다. 디코딩 결과는 소유 스레드로
돌아와 iiGUI 래스터로 전달되며, 뷰가 퇴역한 뒤에는 완료 콜백을 호출하지 않는다.
하나의 로더를 한 뷰에 전용으로 쓰는 호스트는 로더의 동시·대기 한도 합을 뷰의
캐시 항목 한도 이상으로 구성해 정상적인 가시 항목 요청을 대기열에서 잃지 않는다.
실행 중인 디코더를 강제로 중단한다고 보장하지는 않는다. 원격 URL은 읽지 않는다.
타이머로 변경을 검사하거나 사진 전체를 다시 읽지 않는다.

파일 선택 요청은 한 번에 하나만 열며, 취소·뷰 퇴역 후 도착한 이전 선택 결과는
폐기한다. 선택기를 열 수 없거나 비동기 선택에 실패하면 현재 언어의 오류를
사진 상태에 표시한다. iOS에서는 앱 샌드박스에 복사된 임시 파일을 기존 사진
서비스가 컨테이너에 가져온다.

`PhotoAreaTracker`는 기존 화면과 조상의 위치·크기·가시성·클리핑 변경을 관측해
네이티브 표면이 사용할 논리 좌표와 잘린 영역을 전달한다. 같은 이벤트 턴의 변경은
하나로 모으며 같은 결과는 다시 보내지 않는다. 회전·배율 또는 별도 변환이 있는
계층은 지원하지 않는 상태로 보고해 기존 화면으로 돌아갈 수 있게 한다.
Qt의 변환 목록에는 변경 알림이 없으므로 해당 목록을 직접 변경하는 호스트는
`refresh()`를 소유 스레드에서 명시적으로 호출해야 한다. 원본
레거시 항목을 숨기기 위한 그 항목 자체의 불투명도·입력 비활성화는 영역 가시성에
영향을 주지 않지만 조상의 불투명도·비활성화는 영향을 준다.
호스트가 기존 Qt 오버레이 계층을 제공하면, 그 계층에서 보이는 그리기 또는 입력
항목이 있는 동안은 네이티브 영역을 감춰 기존 메뉴·시트가 가려지지 않도록 한다.
화면을 그리지 않는 상시 컨테이너 자체는 표면을 막지 않으며, 그 자식의 생성과
가시성 변경을 관측한다. Qt가 항목의 그리기·입력 플래그 변경 알림을 제공하지
않으므로 호스트가 기존 항목의 플래그를 직접 변경할 때는 `refresh()`를 호출해야 한다.
감시하던 오버레이가 파괴되면 안전한 대체 경로가 필요하다고 보고한다. macOS와 iOS의 네이티브 부모는 사진의
전체 영역을 유지하면서 바깥 클리핑 뷰로 잘린 부분만 표시하도록 준비한다.
Windows 호스트도 전체 사진 영역과 잘린 표시 영역을 분리한다. 논리 좌표의 각 경계를
실제 픽셀 경계로 변환하여 잘린 가장자리와 입력 위치를 일치시키며, Qt의 배율과
iiGUI의 Windows 호스트 배율이 다르거나 부모 창을 안전하게 사용할 수 없으면 기존
레거시 화면으로 돌아간다. 창의 DPI 변경 이벤트에서만 배율을 다시 읽고 표면을 갱신한다.
계정·에이전트 질문 등 같은 창의 네이티브 모달은 별도의 관측 가능한 임대 수를
사용한다. 모달 임대가 남아 있는 동안 사진 호스트는 대기할 수 있으며, 마지막
모달의 실제 종료 이벤트에서만 다시 판단한다.

`tests/native-photo-preview`는 가짜 요청을 이용한 항목별 알림·중복 요청·이전
결과·캐시 한도·재진입과, 테스트용 로컬 이미지의 제한된 비동기 디코딩·소멸을
검사한다. 오프스크린 Qt 창에서 영역의 클리핑·크기·조상 변경, 빈 오버레이
컨테이너와 실제 그리기·입력 자식의 구분, 모달·표면 퇴역도 검사한다.
임시 이미지는 `resources/` 안의 고유한 테스트 디렉터리에 만들고
종료 시 정리한다. 실제 사진 라이브러리와 GUI 앱은 실행하지 않았다.

`tests/native-photo-presenter`는 모의 표면과 실제 QML `var` 바인딩 형태를 사용해
서비스 교체·숨김·모달·종료 시 레거시 화면의 연결과 수명이 보존되는지 검사한다.
오프스크린 Qt Controls 창에서도 오버레이 자동 발견, 빈 호스트, 팝업 열기와
닫기를 검사한다.
별도 테스트는 기존 사진 서비스, 선택적 브리지, 설치 스테이징에서 생성한 LVUI 뷰와
모의 페인트 장치를 조합하여 사진 선택, 메타데이터 변경, 삭제를 확인한다.
사진 정보에는 서비스가 전달한 리소스 크기의 합과 생성 시각을 유형과 함께 표시한다.
2026-11-15에는 이 조합에서 번역된 항목명·크기·시각까지 확인한 두 검사가 통과했고,
로드된 사진 프레젠테이션과 Core가 같은 테스트 스테이징을 사용하는지도 확인했다.
처음 실행한 프레젠터 검사는 기존 30초 제한에서 출력 없이 시간 초과됐다. 원인은
확인하지 못했으며, 같은 제한으로 단독 검사와 두 검사 전체를 재실행해 통과했다.
이 검사는 갱신된 Society 앱 번들이나 시스템 설치본의 실행을 뜻하지 않는다.
한국어 카탈로그의 `ko-KR`과 언어 공통 `ko`는 함께 등록한다.

이는 기존 Qt 앱에 iiGUI 표면을 연결하는 전환 경로이다. 표면 생성이
불가능하거나 회전·배율이 포함된 영역, 기존 Qt 팝업 또는 네이티브 모달이 열려
있는 동안에는 격리된 레거시 화면으로 돌아간다. 호스트는 Qt의 오버레이 객체를
찾지 못하면 사진 화면을 교체하지 않는다. macOS·iOS와 Windows 데스크톱 소스 구성에서
이를 선택하며, Windows Store와 Linux·Android·WebAssembly는 기존 레거시 경로를
사용한다. 실제 GPU 출력, 표시 순서와 실기기 입력은 이 검사에 포함되지 않는다.

iOS에서는 Qt가 소유한 부모 뷰에 별도의 잘림 뷰와 iiGUI 표면을 붙인다. 부모의
화면 배율과 Qt 영역의 배율이 다르거나 장면이 분리된 경우에는 연결을 거부해
기존 화면을 유지한다. iPhoneOS 18 arm64에서 실제 프레젠터·영역 구현과 생성된
LVUI 화면을 객체 파일로 교차 컴파일했다. 문서 선택기의 허용 정책과 선택 요청의
중복·취소·늦은 응답·재진입은 헤드리스 검사로 확인했다. 이 검사는 iOS 앱 전체의
링크, 실기기에서의 모달 표시나 사진 가져오기 완료를 검증하지 않는다.
같은 변경에서 생성된 사진 뷰의 추가 버튼이 호스트 명령을 호출하고 상태 오류를
그리는지 모의 페인트 장치로 확인했고, 300개 항목의 모의 선택 결과가 순서대로
전달되는지도 확인했다. 선택 요청 관리 코드는 Windows x86-64
객체로도 교차 컴파일했으며 Windows 앱 링크나 실행은 수행하지 않았다.

Windows 소스는 기존 Qt 창의 그리기를 대신하지 않는 클리핑 부모와 콘텐츠 자식 창을
소유하고 콘텐츠 창에 iiGUI의 외부 Direct3D 합성 표면을 붙인다. 창 소유 스레드와
부모·자식 관계를 검증하며, 각 자식의 별도 소유 식별값을 확인해 운영체제가 재사용한
핸들을 퇴역 시 잘못 파괴하지 않는다. 부모가 사라지거나 크기·DPI가 유효하지 않으면
표시를 거부한다. 자식이 다른 부모로 옮겨지거나 위치 변경에 실패하면 가능한 자식을
먼저 숨기고 표면 퇴역 후 기존 화면을 복구한다. 위치·크기·배율이 바뀌었을 때만
표면을 갱신하며 이미 적용된 프레임에는 추가 창 위치 변경을 보내지 않는다.
Windows 좌표와 배율의 기준은 [Microsoft의 자식 창 좌표·클리핑 규약](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features),
[GetDpiForWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getdpiforwindow),
[Qt의 창 배율 변경 이벤트](https://doc.qt.io/qt-6/qwindow.html#devicePixelRatio)이다.

2026-11-15 macOS의 모의 창 시스템에서 소수 배율·부모 경계·배율 전환, 잘린
좌표, 생성 실패, 부분 이동 실패, 자식 재부착, 핸들 재사용과 취소·해제를 검사했다.
1.25배 오프스크린 Qt 창의 영역 관측과 기존 사진 브리지·프레젠터 검사도 통과했다.
Windows용 숨긴 부모 창 검사 프로그램과 해당 Win32 드라이버는 MinGW x86-64로
교차 컴파일·링크했지만 실행하지 않았다. 앱 전체의 Windows 링크, Direct3D 출력,
실제 클릭·포커스·DPI 전환은 검증되지 않았다. 앱이나 시스템 설치본은 실행·교체하지
않았다.
이전된 사진 영역 관련 독립 검사 12개와 기존 사진 프레젠터·브리지 검사 2개가
macOS에서 통과했다. 모의 창을 사용하는 클리핑·수명 검사는 별도로
AddressSanitizer와 UndefinedBehaviorSanitizer를 적용해 통과했다. 이 계측은 실제
Windows 창 시스템이나 Direct3D 드라이버를 검사한 것이 아니다.

2026-11-14 macOS에서 `build/module-view-integration`의 Society 타깃을 빌드했다.
빌드 산출물의 의존성 및 크기 검사는 326,114,139바이트·616개 파일로 통과했으며,
번들에 포함된 Core·iiGUI·사진 프레젠테이션이 테스트에 사용한 스테이징과 같은
바이너리인지 UUID로 확인했다. 기존 계정 서비스도 기존 설치본과 같은 바이너리였다.
같은 Core 버전 번호에 서로 다른 ABI가 존재하므로 다른 모든 SDK 라이브러리까지
이 확인만으로 ABI 호환을 보장하지는 않는다. 시스템 설치와 앱 실행은 하지 않았다.

2026-11-15에는 사진 정보 표시를 갱신한 LVUI 선언과 프레젠테이션을 선택해
같은 Society 타깃을 다시 빌드했다. 빌드 스크립트의 서명과 번들 구성 검사가
통과했으며 결과는 326,151,083바이트·616개 파일이다. 번들 안의 사진
프레젠테이션·iiGUI·Core·Core Observation 바이너리 UUID는 위 오프스크린
검사에서 사용한 스테이징과 일치한다. 이 비교는 다른 SDK 전체의 ABI 호환성이나
화면 표시를 증명하지 않는다. 시스템 설치와 앱 실행은 하지 않았다.

같은 날 파일 선택 수명과 오류 표시 변경 후 Society 타깃을 다시 빌드했다.
서명과 번들 구성 검사는 326,285,291바이트·616개 파일로 통과했으며 번들의
사진 프레젠테이션 바이너리 UUID는 이번 테스트 스테이징과 일치한다. 시스템
설치본은 갱신하지 않았고 앱도 실행하지 않았다.
