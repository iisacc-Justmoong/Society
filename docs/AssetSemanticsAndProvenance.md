# Society 에셋 의미와 출처 명세

## 목적과 적용 상태

이 문서는 에셋의 의미를 유형별 스키마와 관계로 표현하기 위한 **목표 제품 계약**이다.
현재 SDK에서 사용할 수 있는 기반과 아직 연결·확인이 필요한 범위는
[기존 구현과 이행 경계](#기존-구현과-이행-경계)에 구분한다. 이 명세는 모든 에셋의
속성별 출처 관리, AI 제안 또는 검증 화면이 현재 구현되었다는 뜻이 아니다.

자원은 이름이나 위치가 아닌 안정적인 자원 ID로 식별한다. 스키마는 그 자원의 의미를
정의하며, 내용 판본·메타데이터 판본·프로젝트 관계·저장 위치의 구분은
[자원 정체성 명세](ResourceIdentityAndProtection.md)를 따른다. 파일에서 읽은 값,
사용자가 입력한 의미, AI가 제안한 정보는 **출처와 검토·검증 상태를 구분**한다.

## 유형별 스키마

유형은 자원에 적용할 수 있는 속성과 관계의 의미·값 종류·선택적 제약을 설명한다.
다음은 초기 예시이며, 모든 필드를 필수 입력값으로 하거나 실제 값이 없는 에셋에
임의 값을 채우라는 뜻이 아니다.

- 유형: 이미지; 유용한 메타데이터와 관계: 픽셀 크기, 색 공간, 제작 도구, 원본·파생 관계; 구분할 점: 파일 구조에서 읽은 값과 파일 안에 적힌 제작 도구 주장을 구분한다. 파생 관계의 대상은 자원·필요한 판본을 참조한다.
- 유형: 모델; 유용한 메타데이터와 관계: 실제 형식, 모델 계열, 라이선스 참조, 런타임 요구 정보; 구분할 점: 파일 형식 확인, 사용자의 계열 지정, 라이선스 주장 및 호환성 검증은 별개의 사실이다.
- 유형: 캐릭터·에셋 묶음; 유용한 메타데이터와 관계: 고유 ID, 설정 자료, 관련 의상·소품·참조; 구분할 점: 캐릭터나 묶음의 논리적 정체성과 그에 연결된 파일·판본·저장 폴더를 구분한다.
- 유형: 배포 자료; 유용한 메타데이터와 관계: 포함 판본, 호환 앱, 제공 파일, 이용조건 참조; 구분할 점: 확정된 릴리스 구성과 배포 후보를 구분하고, 이용조건의 출처와 해당 범위를 기록한다.

유형·속성·관계 정의는 식별자와 스키마 버전, 설명, 값 종류, 단위나 범위, 다중성 및
필요한 관계 대상 제약을 가질 수 있다. 실제 단위와 제약은 각 속성 정의에서 밝힌다.
이미지의 크기는 특정 내용 판본에서 관찰한 값일 수 있고, 캐릭터의 설정 관계는
사용자가 프로젝트 맥락에서 정의한 의미일 수 있다. 하나의 자원에 적합한 여러 유형을
적용할 수 있으며 스키마가 모르는 속성을 무작정 지우지 않는다.

공통 유형과 프로젝트별 확장은 구분한다. 프로젝트가 자원에 부여한 용도나 관계는 그
프로젝트의 맥락을 가지며, 자동으로 다른 프로젝트의 의미·소유권이 되지 않는다.
정의된 관계는 가능한 한 경로가 아닌 대상 자원 또는 개체 ID와 필요한 판본을 참조한다.
관계 대상이 아직 해석되지 않으면 미해결 참조로 보존한다.

## 속성과 관계의 출처

각 속성 값과 관계는 단순한 `키 → 값` 외에 **누가 또는 무엇이, 무엇을 근거로, 어느
대상에 대해 제시했는지** 표현할 수 있어야 한다. 최소한 다음 의미를 구분한다.

- 출처: 파일 검출·관찰; 의미: 지정한 파일 또는 판본을 읽거나 측정하여 얻은 정보; 주의할 점: 검사 대상·방법·시점을 남긴다. 추출한 임베디드 문구의 존재와 그 문구 내용의 진실은 다르다.
- 출처: 사용자 입력; 의미: 사용자가 입력하거나 명시적으로 선언한 정보·관계; 주의할 점: 사용자의 의미와 의도를 보존한다. 입력되었다는 사실만으로 외부 사실이나 권리가 독립 검증되지는 않는다.
- 출처: AI 제안·추론; 의미: 모델 또는 에이전트가 제시한 값·관계; 주의할 점: 제안임을 표시하고 검토 전 확정된 사용자 온톨로지로 취급하지 않는다.
- 출처: 외부 출처 또는 계산; 의미: 외부 자료에서 가져왔거나 알려진 입력으로 계산한 결과; 주의할 점: 자료 제공자·원본 참조 또는 계산 방법과 관찰 가능한 범위를 남긴다. 외부 문구를 가져온 것과 그 내용의 검증은 다르다.

이 분류는 출처의 차원이다. 별도로 제안·사용자 수용·거절·철회 같은 **검토 상태**와
미검증·검증됨·불일치·검증 불가 같은 **검증 상태**를 표현한다. 적용 가능한 검증 방법과
그 결과의 범위도 함께 기록한다. 검증 상태가 비어 있거나 근거를 찾지 못한 것은
`검증됨`도 `거짓`도 아니다.

정보 기록에는 해당 자원 또는 개체 ID, 속성·관계의 정의, 값 또는 대상 ID, 적용 범위와
필요한 내용 판본, 출처 종류, 제공자 또는 작성 주체, 기록 시각과 가능한 근거 참조를
연결한다. 검사기·모델·도구와 버전, 사용자 확인자·확인 시각, 검증 방법과 검증 시각은
알 수 있거나 해당 작업에 필요한 경우 남긴다. 이들은 의미 요구사항이며 저장 형식이나
필수 API 이름을 지정하는 것은 아니다. 알 수 없는 주체·시각·근거를 만들어 내지 않는다.

파일의 특정 판본에서 검출한 크기·형식 등은 그 판본에 연결한다. 새 내용 판본이
만들어지면 이전 관찰을 새 판본에 자동으로 확정하지 않고, 재검사 전에는 이전 관찰의
대상과 최신 여부를 구분한다. 반대로 파일 헤더에 `제작 도구: X`라는 문구가 있을 때
검출된 사실은 그 **문구가 기록되어 있다**는 것이며 X로 실제 제작되었다는 독립
검증은 아니다. 오류·부분 검사·지원하지 않는 형식도 검출 성공과 구분한다.

## AI 제안과 사용자 온톨로지

AI가 제안한 속성이나 관계는 독립된 제안으로 보관한다. 기존 사용자의 값이나 명시적
관계를 조용히 덮어쓰지 않으며, 제안이 기존 값과 다르면 양쪽 출처와 차이를 보여 준다.
사용자가 제안을 수용·수정·거절할 수 있고, 수용하더라도 최초 제안이 AI에서 왔다는
출처와 확인 기록은 보존한다. 사용자 수용은 그 제안을 자신의 의미 체계에 반영했다는
것이지 외부 사실이나 라이선스의 독립 검증을 자동으로 뜻하지 않는다.

AI 신뢰도나 점수가 제공되어도 그것은 해당 제안의 보조 정보일 뿐 검증 증거 또는
권한이 아니다. 출처나 검증 상태가 불명확한 제안은 미확인으로 남긴다. 에이전트가
결과를 조회하거나 수정할 때도 해당 자원·프로젝트의 접근 권한을 따른다.

단일 값 제약이 있는 속성이라도 서로 충돌하는 관찰·주장·미확정 제안은 근거 기록으로
남길 수 있어야 한다. 제안이 확정된 의미의 단일 값이나 관계 제약을 미리 차지하지
않는다. 사용자가 확정된 의미를 바꾸는 시점에는 현재 메타데이터 판본과 스키마 제약을
다시 확인하며, 동시 변경이 있으면 이전 값을 덮어쓰지 않고 충돌을 표시한다.

## 라이선스와 이용 범위

라이선스 또는 이용조건은 그 내용·참조와 출처, 적용 대상 및 해당 내용 판본 또는
릴리스 범위를 구분해 기록한다. 라이선스 문서나 URL을 수집한 사실, 사용자가 지정한
라이선스, 파일에 기재된 라이선스 문구, AI가 추정한 라이선스와 근거를 확인한 결과는
서로 다르다. 문서의 해시는 그 바이트 식별과 무결성을 도울 수 있지만 문서 작성자의
신원이나 실제 권리의 증명 자체는 아니다.

**AI가 추정한 라이선스나 관계는 검증된 사실로 표시하지 않는다.** AI 제안이나
파일명·해시의 유사성만으로 배포 권한, 소유권 또는 이용 허가를 만들지 않는다.
사용자의 수용과 별도의 검증 결과를 구분하며, 확인되지 않은 경우 미확인 상태를
유지한다. 자원의 이용조건 참조와 특정 주체에게 부여된 Grant / Entitlement도
서로 다른 객체다.

## 표시·검색·스키마 변경

에셋 상세 화면은 해당 유형에 맞는 속성과 관계를 보여 주고, 각 값의 출처·적용 판본·
검토 및 검증 상태를 확인할 수 있어야 한다. 미확정 AI 제안과 사용자 선언을 구분하고
제안의 수용·수정·거절을 지원한다. 알 수 없는 값, 명시적으로 비어 있는 값, 확인에
실패한 값을 같은 값으로 표시하지 않는다. 조회·필터·에이전트 응답에도 출처와 상태를
전달하여 제안이 확인된 사실인 것처럼 섞이지 않게 한다.

스키마 변경은 정의의 버전과 적용 범위를 기록한다. 새 속성 추가나 기존 정의 변경
과정에서 이전 값·관계·출처 및 알 수 없는 확장을 조용히 삭제하지 않는다. 기존 값이
새 제약과 충돌하거나 읽을 수 없는 스키마를 만나면 원본과 이력을 보존하고 명시적으로
오류 또는 검토 필요 상태를 표시한다. 스키마에 맞는 값이라는 사실은 그 값의 내용이
현실에서 참이거나 권리가 유효하다는 증명이 아니다.

검출·색인·AI 제안은 [공통 작업 모델](JobsAndOperations.md)과 판본 이벤트 계약을
따른다. 늦게 도착한 이전 판본의 관찰이 최신 판본의 값을 덮어쓰지 않으며, 작업의
실패는 해당 자원과 판본에서 확인·재시도할 수 있어야 한다. 메타데이터나 의미 관계만
바뀐 경우 내용 바이트를 수정하거나 새로운 내용 판본을 만들지 않는다.

## 기존 구현과 이행 경계

- iiFileProvider의 `OntologyFileSystem`은 ObjectStore 파일 키와 업무 개체를 구분하고,
  클래스·속성·값 종류·관계·일부 제약·그래프 journal을 제공한다. 현재 공개
  `OntologyAssertion`의 필드는 주체·속성·값·존재 여부이며, 이것만으로 모든 속성의
  출처·검토·독립 검증 상태가 저장된다고 가정하지 않는다. 이 API는 전체 RDF/OWL
  추론이나 SPARQL 엔진이 아니다.
  [온톨로지 계약](../../../SDK/iiFileProvider/docs/ONTOLOGY_FILESYSTEM.md)
- iiFileProvider Presentation은 파일의 일부 형식 정보와 프리뷰를 제공하고,
  ObjectStore는 파일 및 메타데이터 변경 이력을 제공한다. 현재 ObjectStore의
  메타데이터 변경도 객체 버전을 늘릴 수 있으므로, 그 버전을 이 명세의 **내용 판본**과
  무조건 동일시하지 않는다. [Presentation](../../../SDK/iiFileProvider/docs/FILE_PRESENTATION.md),
  [파일 journal](../../../SDK/iiFileProvider/docs/FILE_JOURNAL.md)
- iiProjectManager는 프로젝트 관계에서 `user_asserted`, `observed`, `inferred` 출처를
  구분한다. 미확정 추론은 기본 관계 조회에서 제외하며, 사용자 확인 후에도 원래
  추론 출처와 확인자를 유지한다. 이는 프로젝트 관계에 대한 기존 기능이며 Society
  전체 에셋의 모든 속성·검증 상태가 이미 관리된다는 뜻은 아니다.
  [프로젝트 설계](../../../SDK/iiProjectManager/docs/Design.md)
- 기존 프로젝트 리소스 ID, ObjectStore 키, Catalog 키와 공통 자원 ID의 연결은
  [자원 명세의 이행 경계](ResourceIdentityAndProtection.md#기존-구현과-이행-경계)를
  따른다. 서로 다른 저장소의 ID나 의미 범위를 추측해 통합하지 않는다.

구현 시 기존 SDK의 타입·관계·이력 계약을 재사용하거나 필요한 인터페이스를 확장한다.
GUI가 도메인 데이터의 유일한 소유자가 되지 않도록 하고, 포맷별 검출과 의미 저장·
권한 판단을 분리한다. 기존 사용자 데이터, 프로젝트 그래프와 미확정 제안을 보존한다.

## 구현 시 수용 검증

1. 이미지·모델·캐릭터 묶음·배포 자료에 서로 다른 스키마를 적용하고 모르는 값은
   임의로 생성하지 않는다. 한 자원에 여러 적절한 유형을 적용할 수 있다.
2. 파일에서 검출한 값, 사용자 선언, 외부 자료와 AI 제안이 같은 속성을 가리켜도
   각각의 출처·범위·상태를 보존하고 충돌을 표시한다.
3. 임베디드 제작 도구 또는 라이선스 문구를 읽어도 실제 제작 사실이나 권리를
   자동으로 검증된 것으로 만들지 않는다.
4. AI가 제안한 라이선스와 관계는 사용자 값이나 확정 관계를 덮어쓰지 않는다.
   사용자가 수용해도 AI 출처와 확인 이력이 남고 독립 검증 상태는 별도로 유지한다.
5. 검출 결과의 내용 판본을 고정하고 새 판본으로 바뀐 후 이전 검사 이벤트가 늦게
   와도 최신 판본의 관찰을 덮어쓰지 않는다.
6. 사용자·에이전트의 동시 수정이나 스키마 제약 위반에서는 기존 값·관계와 이력을
   보존하고 충돌 또는 오류를 반환한다.
7. 프로젝트별 의미는 다른 프로젝트의 사용자 의미나 소유권으로 자동 승격되지 않고,
   자원의 위치 변경 뒤에도 ID 기반 참조가 유지된다.
8. 스키마를 갱신하거나 지원하지 않는 확장을 읽을 때 기존 의미와 출처를 손실 없이
   보존하고, 미지원 핵심 변경은 조용히 덮어쓰지 않는다.
9. 원본 에셋의 메타데이터만 변경했을 때 내용 판본과 원본 바이트는 바뀌지 않는다.
   색인·에이전트 조회는 미확정 제안의 출처와 상태를 유지한다.
10. 라이선스 주장·검증 결과·주체별 이용 권한을 분리하고 AI 추정이나 같은 해시를
    근거로 소유권 또는 이용 권한을 만들지 않는다.
